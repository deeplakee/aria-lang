# compile 层模块参考

Lexer / Parser 的实现应与 `docs/grammar.txt`（语言文法规范，留在 `docs/`）保持一致，改文法时同步更新相关代码与测试。

- `compile/Token.hpp`：`TokenType`（覆盖文法全部终结符，含 24 关键字）/ `Token`（type+lexeme(`StringView`)+loc+`TokenValue`，工厂 `make_integer`/`make_float`/`make_string`/`make_error`）/ `lookup_keyword`。`TokenValue = variant<monostate,i64,f64,String>`。访问器 `type()`/`lexeme()`/`loc()`；谓词 `is_eof()`/`is_error()`/`is_literal()`/`is_keyword()`/`is_operator()`/`is_punctuation()`；取值 `int_value()`/`float_value()`/`string_value()`。自由函数 `token_type_name(TokenType)` 返类型可读名（`Token.cpp` dump 渲染用）。
- `compile/Lexer.hpp`：`Lexer::tokenize(SourceFile*) -> Result<List<Token>, List<Error>>`。错误恢复式词法分析：词法错误记入 `List<Error>` 后推进继续扫，达 `kMaxErrors`(=32) 置 `is_fatal_` 停止；无错才返回 token 流（含末尾 Eof）。基于 `utf8::decode_one` 按码点推进，`src_` 以 `\0` 结尾作哨兵。Lexer 空态可复用（多次 tokenize）。
- `compile/ast.hpp`：AST 节点层次（`ASTNode` 根 -> `StmtNode`/`ExprNode`/`PatternNode` 分类基 -> 各具体节点；`ProgramNode : ASTNode` 为根的直接子节点，持顶层声明列表）。`ASTNode` **不可拷贝、不可移动**（节点总经 `UPtr` 堆分配，移动的只是指针），运算符枚举 `Op::Binary`/`Op::Unary`/`Op::Assignment`（收口于 `namespace Op`，与 `TokenType` 解耦；`Op::to_string(Binary/Unary/Assignment)` 返运算符字面），辅助值类型 `Param`/`MatchPattern`/`MatchArm`/`MatchExprArm`/`VarBinding`/`MapEntry`/`DefMember` 等。节点持 `SourceLoc`，`loc_line()` 取行号（`static_cast<u32>(loc_.line())`，无 0->1 兜底），`dump(indent)`/`display()` 渲染树形文本。每个具体节点有 `accept(AstVisitor&)` override（双分派：节点调 `visitor.visitXxxNode(this)`，见 `compile/AstVisitor.hpp`）。
- `compile/Parser.hpp`：`Parser::parse(List<Token>) -> Result<UPtr<ProgramNode>, List<Error>>`。递归下降，各函数与文法非终结符一一对应；内部用 `AriaCompileException` 在递归下降深处传播语法错误，`declaration()` 层捕获 + panic-mode `synchronize()` 恢复式收集 `List<Error>`（同 Lexer）。游标辅助 `peek(ahead=0)`/`check(t)`/`match(t)`（= check+advance）/`advance()`/`previous()`/`expect(t, what)`（失配抛 `AriaCompileException`）/`expect_identifier()`/`synchronize()`；for/for-in、fun 声明/lambda、`{` block/mapExpr 等按调用上下文消歧。Parser 空态可复用（多次 parse）。
- `compile/AstVisitor.hpp`：AST 访问者（Visitor）模式接口，作为代码生成阶段「字节码编译器」（AST -> CodeUnit）与语义分析器等遍历类的抽象父类。每个具体 AST 节点对应一个 `visitXxxNode(XxxNode*)` 纯虚方法（子类须逐一 override，编译器据此强制覆盖全部节点类型，避免漏处理）；双分派由节点的 `accept(AstVisitor&)` 完成（见 `compile/ast.hpp`）。本头只前置声明各节点类型（只用节点指针，与 `ast.hpp` 解耦），子类需自行 include `ast.hpp` 访问节点成员。参数用非 const 裸指针（子类可在遍历中读写节点）。具体子类：`CodeGen`（见下）。
- `compile/FunctionCtx.hpp`/`.cpp`：单函数编译上下文，收口每函数可变状态。持 `enclosing_`（外层上下文裸指针；所有权：入口 fn 上下文由 `ModuleCtx` 构造期 `new`、析构沿 enclosing_ 链 `delete`；子上下文由 `compile_function` `new`--成功路径 `delete`、出错路径不 delete 交 `~ModuleCtx` 走链。父函数编译期长于子函数（栈帧包住），故 `enclosing_` 裸指针在子生命期内稳定；`enclosing_==nullptr` 即入口 `<main>`）、`fn_`（当前函数；其 CodeUnit 由 CodeGen 经 `cur_cu()` 派生（= `&fn_->unit()`，随 ModuleCtx 游标），**不缓存 `cu_` 于本类**）、`locals_`（clox 风格局部栈，`locals_[0]`=哑元 slot 0=callee；1..A=形参；A+1..=体局部）、`scope_depth_`、`loop_stack_`（循环上下文栈）。入口构造 `FunctionCtx(ObjFunction&)`（`enclosing_=nullptr`）；嵌套构造 `FunctionCtx(FunctionCtx& enclosing, ObjFunction&)`。**只负责登记**：`add_local(name)` 压 `Local{name,scope_depth_,is_captured=false,is_initialized=false}` 返 slot（纯登记，不发射/不查重）；`mark_initialized(slot)`/`is_initialized(slot)` 置/查初始化状态（CodeGen 在初始化器求值/无初始化器发 `LOAD_NIL`/赋值后 `mark_initialized`，读取前查 `is_initialized` 未初始化 -> `fail UninitializedVariable`）；`is_defined_in_scope(name)` 当前 scope 是否已定义同名（外层同名允许 shadow）；`find_local(name)` 返最近同名 slot；`begin_scope`/`end_scope_pop_count`（`--scope_depth_` 后弹比新 scope_depth_ 更深的局部 = 原 scope 的局部，返弹出数交调用方 emit POP_N）；`pop_locals_deeper_than(target_depth)`（弹 depth>target 的更内层局部，返弹出数，不改 scope_depth_）--**仅 `end_scope_pop_count` 退出作用域用此**（真正从编译期 `locals_` 移除，局部出作用域后续不可再引用）；`count_locals_deeper_than(target_depth)`（const，仅计数不弹出，不改 `locals_`/`scope_depth_`）--break/continue 跳出循环用此：只 emit `POP_N`（运行期弹栈），不破坏编译期 `locals_` 登记（跳转后的语句仍在作用域内可引用这些局部，只有 `end_scope` 才真正移除）。`Local`/`LoopCtx` 为 `aria` 命名空间下简单聚合（见头文件）。`LoopCtx`：`continue_back_target`（while/for-in/for 无 incr 后向跳目标）/`continue_fwd_patches`（for 有 incr 前向跳 L_incr 回填）/`loop_scope_depth`（循环体 scope 深度，break/continue 弹局部至此）/`break_fwd_patches`（待回填 JUMP 占位偏移）。构造统一经头文件内联工厂 `make_loop_ctx(loop_scope_depth)`（`continue_back_target=nullopt`、两个 patch 列表空，全字段显式初始化收口于一处），调用方按循环类型在入栈前给 `continue_back_target` 赋值（while/for-in -> L_start、for 无 incr -> L_cond；for 有 incr 留空走前向）。**循环上下文随函数走**：进新函数即得空 `loop_stack_`，故 break/continue 不会跨函数绑定到外层循环（函数边界天然隔离循环上下文）。`LoopCtx` 字段语义与三种循环（while/for/for-in）+ break/continue 的占位回填用法详见 `.claude/reference/compile/loopctx.md`。
- `compile/ModuleCtx.hpp`/`.cpp`：模块编译上下文，收口每模块状态--模块句柄 `module_`（`ObjModule*`）+ 当前函数上下文游标 `current_fn_ctx_`（`FunctionCtx*` 裸指针，公有，**兼拥有入口 fn 上下文**：构造期就 `m.entry()` `new`、析构 `delete`）+ 顶层全局名注册表 `defined_globals_`（`HashSet<String>`，按名字**内容**判等，不依赖 intern 指针，私有）。**单成员兼两职**：`current_fn_ctx_` 既是入口 fn 上下文的所有者（ctor 分配 / dtor 释放），又是「当前编译到哪个函数」的游标--初始 = 入口（`enclosing_==nullptr`=entry）。子函数上下文由 `compile_function` `new` 分配、enclosing_ 回父、游标摆向子（`mod_ctx_->current_fn_ctx_ = child`）；**成功**路径 compile_function 还原游标（`= child->enclosing_`）并手动 `delete child`，**出错**路径 `fail()` 抛 `AriaCompileException` unwind（不还原游标、不 delete 子，见 CodeGen）。无需另设 owner + cursor 两个指针。「当前 CodeUnit」不再单独存，由 CodeGen 经 `cur_cu() = &cur_fn_ctx()->fn_->unit()` 派生，随游标自动切换（免两指针同步 save/restore）。entry 判定 = `current_fn_ctx_->enclosing_ == nullptr`。**析构走链**：`~ModuleCtx` 沿 enclosing_ 链从 `current_fn_ctx_` 走到 entry 逐个 `delete`（先存 next 再 delete），无论游标在哪儿都对--成功时游标 = entry 仅删 entry，出错时游标停在 deepest 未释放子，走链释放整条活动链 + entry。无需「游标必回入口」不变式与 ASSERT：异常 unwind 保证出错后无 cur_cu()/cur_fn_ctx() 访问（见 CodeGen），析构走链即清理。**轻封装**：`module_` / `current_fn_ctx_` 公有（CodeGen 直接读写--后者在 `compile_function` 进出函数时摆动），`defined_globals_` 私有（仅经内联方法 `declare_global` 访问）；一个内联方法 `declare_global(StringView name)`（`return defined_globals_.insert(String{name}).second`，true=新登记 / false=已存在，调用方 `fail RedefinedVariable`）；另一定义于 .cpp 的 `is_global_scope() const noexcept`（`current_fn_ctx_->enclosing_ == nullptr && current_fn_ctx_->scope_depth_ == 0`，收口「当前是否模块顶层作用域 -> 定义为全局」判定，供 `visitVarDeclNode`/`compile_function` 复用，需 `FunctionCtx` 完整类型故非内联）。构造函数 `ModuleCtx(ObjModule& m)`（.cpp 定义）：**要求调用方先 `module.set_entry(entry)`**，构造期 `ASSERT(m.entry() != nullptr)`，`module_{&m}` 后 `current_fn_ctx_ = new FunctionCtx(*m.entry())`（自建入口 fn 上下文 = 游标就位）。与 `FunctionCtx`（每函数）对齐：模块 > 函数 > 作用域 三层各一席。**一次性**：不复用、无 `reset`，每个模块编译用全新实例（`CodeGen::init_module` 入口 `std::make_unique<ModuleCtx>(module)`）。**特殊成员**：`current_fn_ctx_` 是 `new` 分配的裸指针，析构沿 enclosing_ 链 `delete`（需 `FunctionCtx` 完整类型，故 `~ModuleCtx()` 声明于头、定义于 .cpp）；copy / move 删除（ModuleCtx 一次性、不可移动）--由调用方以 `UPtr<ModuleCtx>` 持有（CodeGen 持 `UPtr<ModuleCtx> mod_ctx_`，compile 入口 `make_unique`、遍历后 `reset()`、`~CodeGen` 自动释放），无需 move。`gc_`（共享引用）**留 `CodeGen`** 不入此。首错经 `AriaCompileException` 抛出即 unwind（CodeGen 无 `error_` 成员），天然「整个 pass 的第一个错停住」（将来一次 pass 编译多模块时，模块 1 的异常即中断整 pass）。
- `compile/CodeGen.hpp`/`.cpp`：字节码代码生成器 `CodeGen final : AstVisitor`，单遍合一（clox 风格）--一次 AST 遍历同时做名字解析 + 语义检查 + 字节码发射，把 `ProgramNode` 编译为模块入口 `ObjFunction*`（arity 0、名由 `compile` 的 `entry_name` 参数定：主入口模块传 `<main>`、运行期导入模块传 `<module>`，模块体包装）。状态分离：每函数可变状态交 `FunctionCtx`，每模块状态（模块句柄 + 当前函数上下文游标 `current_fn_ctx_`（兼拥有入口 fn 上下文：ctor `new`、dtor `delete`）+ 顶层全局名注册表）交 `ModuleCtx`（见 `compile/ModuleCtx.hpp`），形成「模块 > 函数 > 作用域」三层。`CodeGen` 持 `UPtr<ModuleCtx> mod_ctx_`（ModuleCtx 一次性、不可移动；compile 入口 `make_unique<ModuleCtx>(module)`、遍历后 `reset()` 即释放、`~CodeGen` 自动释放作安全网；编译期间非空，编译外为空）；「当前函数」不再作 CodeGen 成员--游标 `current_fn_ctx_` 寄存于 `ModuleCtx`（公有），CodeGen 经内联 `cur_fn_ctx()`（= `mod_ctx_->current_fn_ctx_`）只读访问、`compile_function` 经 `mod_ctx_->current_fn_ctx_ = ...` 摆动；「当前 CodeUnit」不再单独存，由 `cur_cu()`（= `&cur_fn_ctx()->fn_->unit()`，.cpp 定义需 ObjFunction 完整类型）派生，随游标自动切换（免两指针同步 save/restore）。`module_` / `current_fn_ctx_` 公有、`defined_globals_` 私有，CodeGen 直接经 `mod_ctx_->` 读写（前者）/经 `declare_global` 访问（后者）。**emit 解耦**：字节码编码逻辑（`emit_op`/`emit_byte`/`emit_word`/`emit_pop_n`/`emit_jump`/`patch_jump`/`emit_jump_back`/`emit_load_local`/`emit_store_local`/`size`）**下沉 CodeUnit**（见 `bytecode/CodeUnit.hpp`），CodeGen 不再自持这些薄包装；发射目标由 `cur_cu()`（派生自 ModuleCtx 游标 = 当前函数 `fn_->unit()`）决定。游标在 `compile_function` 进/出函数时摆动，`cur_cu()` 随之自动切到子/父 unit，无需 save/restore。越界（跳转偏移/回边超 64KB）由 CodeUnit 方法返 bool，CodeGen 经失败翻译层 `patch_jump_or_fail(src_off,loc)`/`emit_jump_back_or_fail(target_off,line,loc)` 翻译为 Error。**单层 _or_fail（操作 + 失败即 fail）**：`add_constant_or_fail(Value,loc)->u16`（溢出 `>kMaxConstants` -> `fail CodeUnitTooLarge`，否则 `cur_cu()->add_constant` 返索引；CodeUnit 内部 ASSERT 兜底永不被触达）、`add_name_or_fail(s,loc)->u16`（`new_string` intern 后经 `add_constant_or_fail` 入池，复用溢出检查，无守卫--trivial push 不触发 GC）、`declare_local_or_fail(name,loc)->u16`（同 scope 重名 -> `fail RedefinedVariable`、`>kMaxLocals` -> `fail TooManyLocals`，否则 `add_local` 纯登记标未初始化、不发指令）、`resolve_name_or_fail(name,loc)->ResolvedVar`（局部 -> Local / 外层 -> Upvalue / 否则 Global 分支经 `add_name_or_fail` 入池，溢出即 `fail` 持 loc）供 visit 层（有节点 loc）调用：失败即 `fail(...)`（`[[noreturn]]`，之后值恒有效）并**返回解包值**；`patch_jump_or_fail(src_off,loc)->void`/`emit_jump_back_or_fail(target_off,line,loc)->void`/`declare_global_or_fail(name,loc)->void` 同一职责约定但底层返 bool、无解包值，故 void 封装仅翻译失败。原「两层」（底层薄封装 `add_constant/add_name/declare_local/resolve_name` 返 `Opt`/`Result` 只做操作+失败信号不持 loc + 上层 `_or_fail` 翻译）已收敛为单层--每个薄封装唯一消费者即对应 `_or_fail`，透传空转，故内联至 `_or_fail`（`add_name_or_fail` 经 `add_constant_or_fail` 复用溢出检查免拷逻辑；`declare_local_or_fail` 的 switch+UNREACHABLE 退化为两行直白 `if...fail`）。与 CodeUnit 跳转 bool 同一层次约定。**局部初始化状态追踪**（`Local::is_initialized`）：`declare_local_or_fail` 仅 `add_local` 登记、置 `is_initialized=false`（不发 `LOAD_NIL`，非 clox 预占槽）；调用方在初始化器求值（值恰好压在 slot）或无初始化器发 `LOAD_NIL` 后 `mark_initialized`。**关键不变式**：任意时刻所有已声明局部均已初始化（declare 与 init 原子相邻），故「下个局部 slot = 当前栈高」，初始化器/`LOAD_NIL`/`LOAD_CONST` 值恰好压在 slot 成为该局部，无需 store/pop。**读取未初始化局部 -> `fail UninitializedVariable`**（Python 风格 definite-assignment，避免放弃预占槽后 `var x = x + 1` 读未填充槽）：检查在**读点**（`load_local`，由 `visitIdentifierNode` Load 分支调用），不在 resolve（resolve 亦服务纯写目标 `x = 5`）；`visitIdentifierNode` Store 分支 `mark_initialized`（赋值即初始化）。for-in `<iter>`/pattern 亦用值填槽（见下 for-in lowering），值填槽不变式对所有局部成立，无例外。形参 caller 压栈后 `mark_initialized`。**上下文所有权**：入口 fn 上下文由 `ModuleCtx` 的 `current_fn_ctx_` 自拥有（构造期 `new FunctionCtx(*m.entry())`，`~ModuleCtx` 沿 enclosing_ 链 delete）；`compile_function` 建子上下文 `new FunctionCtx{*cur_fn_ctx(), *fn}`（enclosing_ 回父），**成功**还原游标（`= child->enclosing_`）并 `delete child`，**出错**不还原不 delete 直接 return--交 `~ModuleCtx` 沿链释放。**错误通道**：与 Parser 同--编译期深层 `fail()` 抛 `AriaCompileException`（持 `Error`，`[[noreturn]]`），自动 unwind 跨 visit 递归栈，`compile()` 顶层 `catch (AriaCompileException& e)` 翻译为 `Result`（`mod_ctx_.reset()` 后 `return std::unexpected(e.error())`）。无需 `error_` 成员 / `ok()` / 各 visit 的 `if(!ok()) return` 守卫--throw 即 unwind，首个错误自然即止。unwind 时 `compile_function` 的 `delete child` 与还原游标被跳过，子留在 enclosing_ 链上，`~ModuleCtx` 走链清理。`compile(ProgramNode&, ObjModule&, StringView entry_name = "<main>") -> Result<ObjFunction*, Error>`：入口 `gc_.make_guard(&module)` 把 module 入临时根贯穿全程（**GC 已启用**，同 `run()`）：经 `module.entry_ -> 常量池 -> 嵌套 fn 常量池 -> ...` 整链根化建设中 ObjFunction/常量池 ObjString；每个子 fn 在 `compile_function` 起始即 `add_constant_or_fail` 入父常量池（先于编译体），入池即经 module 根链可达；`new_object -> add_constant` 间走 trivial 分配（`constants.push`/`reallocate`），按 `GC.hpp` 核心不变式不触发 GC，故该窗口无需守卫。调 `init_module(module, entry_name)`（建入口函数 `new_function(...)`（名 `entry_name`）+ `module.set_entry(entry)` + `mod_ctx_ = std::make_unique<ModuleCtx>(module)`（构造期 ASSERT entry 非空并自建入口 fn 上下文 = 游标就位），返回入口函数）；`try { 逐顶层声明 emit_stmt + 隐式 LOAD_NIL; RETURN（经 cur_cu()） } catch (AriaCompileException& e) { mod_ctx_.reset(); return std::unexpected(e.error()); }`，末尾 `mod_ctx_.reset()` 释放本模块上下文（`~ModuleCtx` 沿 enclosing_ 链 delete，成功时仅入口），成功返入口函数，失败返首错。`~CodeGen` 自动释放 `mod_ctx_`（UPtr 安全网，已 `reset()` 则 no-op）。**栈契约**：ExprNode 子类留一值、StmtNode 子类留零值；父 visit 显式调 `emit_expr`/`emit_stmt` 编排子节点（出错由 `fail()` 抛异常 unwind，无需逐调用短路）；所有底层 emit 经 `cur_cu()->emit_*`。**行号线程化**（不再持 `line_` 成员）：行号是「当前发射节点的行」属每节点局部状态，故每个直接发射的 visit 持局部 `const u32 line = node->loc_line()` 并传给 `cur_cu()->emit_*(.., line)`（尊重 CodeUnit「emit 一律带 line、无状态」设计）；`bind_pattern(pat)`/`compile_function(...)` 就地取 `pat->loc_line()`/`body->loc_line()`，`declare_local_or_fail(name)` 不发指令（纯登记），故不带 line；无初始化器时由调用处（`visitVarDeclNode`）就地发 `LOAD_NIL` 并自带行号（`ASTNode::loc_line()` 即 `static_cast<u32>(loc_.line())` 的薄封装，无 0->1 兜底，直接取 loc 原行号）。`emit_expr`/`emit_stmt`/`add_constant_or_fail`/`add_name_or_fail`/`declare_local_or_fail`/`resolve_name_or_fail`/`begin_scope`/`emit_lvalue`/`validate_lvalue_target`/`validate_params`/`patch_jump_or_fail` module 根链可达）+ 父（当前 `cur_cu()`）常量池 `LOAD_CONST fn_idx`；顶层 fun -> `DEF_GLOBAL`（`declare_global_or_fail(name)` 内容判重 + `add_name_or_fail(name)` 入池，与 var/import 同形）、嵌套 fun -> `declare_local_or_fail`+`LOAD_CONST`+`mark_initialized`（值填槽：fn 值恰好压在 slot 即该局部，无 store/pop）、lambda(name=="<anonymous>") -> 留栈不绑定；形参 caller 压栈，编译期 `add_local` 后 `mark_initialized`；`new `mod_ctx_->current_fn_ctx_ = child->enclosing_;` 摆回父 + `delete child`（无 cu save/restore）。出错则 `emit_stmt(body)` 内 `fail()` 抛异常 unwind，跳过 delete/还原，子留链交 `~ModuleCtx` 走链。**import 按作用域绑定**：`visitImportStmtNode` 按 `is_global_scope()` 分派，与 `var`/`fun` 同形 lowering。`IMPORT path:u16` 仅压模块值于栈顶（`[...] -> [..., module]`），绑定由 CodeGen 走：顶层 -> `IMPORT` + `mark_initialized`，无 `STORE_LOCAL`。对齐文法「绑模块到当前作用域（函数体=局部）」。**GC 根纪律（启用 GC 后）**：`new_string` 返回的 name 串是 weak root（intern 不保命），裸持跨任何可能触发 `maybe_collect` 的子编译/分配即可能被扫。故 `compile_function` 内部 intern 的 `add_constant_or_fail`，无跨调用裸持）、`visitImportStmtNode` 的 path/alias 经 `add_name_or_fail`（`new_string` 结果立即 `add_constant_or_fail` 入池，无跨调用裸持；path 入池即经 module 根链可达，alias 的 `new_string` 值填槽 + `mark_initialized`（无 `LOAD_NIL`/`STORE_LOCAL`/`POP`）。每轮开 per-iteration scope：`LOAD_LOCAL <iter>` 后经 `emit_method_call0("has_next", ...)` / `JUMP_FALSE L_end`，再 `emit_method_call0("next", ...)` - `compile/Compiler.hpp`/`.cpp`：编译编排器 `Compiler`，收口「源文件 -> 可执行 `ObjFunction`」端到端链路（此前仅在 `tests/test_codegen.cpp` 辅助函数手拼）。本身不做词法/语法/代码生成/磁盘 I/O--按序串联 `Lexer` -> `Parser` -> `CodeGen`，把三阶段 `Result<..., List<Error>>`（词法/语法，取 `errors_[0]`）/`Result<..., Error>`（CodeGen 已是单 Error）统一翻译为单个 `Result<ObjFunction*, Error>`（首错即止）。**吃实际的 `SourceFile`，不捏造源**：`compile()` 入参为 `SourceFile&`（调用方加载/构造的真实源文件--磁盘文件经 `SourceFile::from_path` 读盘、REPL/嵌入由调用方按需构造），本类只读其 `content()` 做词法，不拥有、不重建源文件；无 `source_` 成员、无 `source_name` 参数--源的身份（name/path）就是 `SourceFile` 自带，错误渲染 `path:line:col` 取自实际源文件。**`SourceFile` 生命期契约**：AST 节点持 `SourceLoc`（内含 `SourceFile*`），但 AST 仅 `compile()` 内部消费、不外返；编译失败返回的 `Error` 在构造期已把 `SourceLoc` 烘进自有 `message_` 串、不再持 `SourceFile*`。故 `source` 只须存活到 `compile()` 返回（烘位置串在此时完成），返回的 `Error`/`ObjFunction` 均不依赖 `source`，调用方可立即释放/move `source`（`SourceFile` 含 `String`，SSO 短串 move 会改 content 地址，但 `Error` 已不指向它，无影响）。成功路径返回的 `ObjFunction` 不依赖 `source`。**可复用**：`Lexer`/`Parser` 均按「空态可复用」设计（`tokenize`/`parse` 扫完即清空成员），作本类成员 `lexer_`/`parser_` 跨多次 `compile()` 复用（如 REPL 逐行重编译）；`CodeGen` 一次性、状态局限单次编译（持 `UPtr<ModuleCtx>`），故每次 `compile()` 内就地构造。**GC 同源**：构造取 `GC&`（与 VM 同一 GC），编译期分配的 `ObjFunction`/`ObjString` 归此 GC、与后续 `run()` 同源；编译期 GC 已启用--`CodeGen::compile` 入口 `make_guard(&module)` 自守 module，故调用方无需为编译期再守模块（module 须是 GC 管理的合法 `ObjModule`）。接口 `compile(SourceFile& source, ObjModule& module, StringView entry_name = "<main>") -> Result<ObjFunction*, Error>`：成功返入口 `ObjFunction*`（arity 0、名 `entry_name`，归属 gc、须在 gc 存活期使用）；失败返首错 `Error`（位置串在构造期由 `source` 的 `SourceLoc` 烘出、此后自有，不指向 `source`）。`entry_name` 透传给 `CodeGen`：主入口模块传 `<main>`（默认）、运行期导入模块传 `<module>`（由 VM 加载层调用时显式传入，区别于主入口）。与 `CodeGen` 分工：`CodeGen` 是「AST -> CodeUnit（包在 `ObjFunction`）」代码生成器；`Compiler` 是「`SourceFile` -> AST」(`Lexer`/`Parser`)+「调 `CodeGen` 产出 `ObjFunction`」编排层，不做磁盘 I/O（加载源文件是解释器入口/REPL 职责）。非拷贝/非移动。测试 `tests/test_compiler.cpp`：经 `Compiler` 编排层端到端 `compile -> AriaVM::run`（非手拼），`SourceFile` 经 `unique_ptr` 持堆稳定地址活到检视完返回值/错误；含算术/递归/全局+while/编译期 `UninitializedVariable`（函数体内局部自引用；顶层 `var x = x + 1` 是全局自引用，编译期合法、运行期才 `UndefinedVariable`）/语法错误，stress GC 锻炼编译期+运行期根接线。
