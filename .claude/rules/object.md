# object 层模块参考

- `object/Object.hpp`：`Object` 基类（`next_` 链/`hash_`/`type_`/`is_marked_`）+ `ObjType`（BASE/STRING/FUNCTION/NATIVE_FN/UPVALUE/CLASS/INSTANCE/BOUND_METHOD/LIST/MAP/MODULE/RANGE/ITERATOR/EXCEPTION/CLOSURE）；虚 `trace(GC&)`/`size()`/`equals(const Object*)`（== 内容相等，默认 `this==other`，子类型按内容 override）/`to_string()`（基类默认 `<Type at 0xaddr>`，子类型 override）/`~Object`；`debug_repr()`（**非虚**，产出 `<Type at 0xaddr>` 地址型描述，`to_string()` 基类默认委托之；供 `format_value_debug` default 分支等不可重入调试上下文调用--不经虚分派，避免重载 `to_string()` 重入 VM）；公共访问器 `hash()`/`type()`/`is_marked()`/`mark()`/`unmark()`（GC 标记用）/`type_name()`（非虚 constexpr，委托 `to_string(ObjType)` 取 `type_` 的 PascalCase 类型名如 `String`/`NativeFn`/`Module`，供错误消息类型名打印与默认 `to_string` 渲染；类型名纯由 `type_` 决定故子类无需 override）。地址哈希经 `util::hash_addr` + 两 ctor（内容哈希 `Object(u32,ObjType)` / 地址哈希 `Object(ObjType)`）。`as<T>` 有 `Object*`/`const Object*` 两重载、`is<T>` 单 `const Object*` 重载（`Object*` 实参隐式转换；DEBUG `dynamic_cast`，否则 `static_cast`；`is<T>` 目前一律 `dynamic_cast`，性能敏感后可改 `ObjType` 查表）；`try_as<T>` 检查式转换（is+as 合一：匹配返 `T*` 否则 nullptr，含 null 入参，`Object*`/`const Object*` 两重载）。**类型判断/转换约定（强制）**：三件套分工--纯谓词（断言 / 否定式 fail-fast / 不需要指针）用 `Object::is<T>(obj)`；「守卫后使用」成对场景优先一步 `Object::try_as<T>(obj)`（类型只写一次，消除 is/as 双类型参数漂移笔误；DEBUG 单次 dynamic_cast 优于成对的两次）；`switch (obj->type())` 臂内等静态已知场合用 `Object::as<T>(obj)`（NDEBUG 裸 cast 不校验）。`switch (obj->type()) { case ObjType::X: ... }` 多分支分派（如 `AriaVM::call_value`）属枚举分派天然合理，保留枚举写法、不必硬改。**禁写 `obj->type() == ObjType::X` + `static_cast<X*>(obj)`** -- 三件套自文档化且 DEBUG 享 dynamic_cast 校验、收口类型转换。从 `Value` 出发的「守卫后使用」用 `value/ObjBridge.hpp` 的 `try_obj<T>(v)` 一步收口（= `is_obj()` + `try_as` 合一，非对象/类型不符返 nullptr）；分步场合仍先 `v.is_obj()` 判对象，再 `Object::is/as<X>(v.as_obj())`（`Value` 类体在两 boxing 头里各一份，typed 成员会双份重复，故 Value 层 typed helper 走独立小头而非成员）。`Object.hpp` 不 include `value/Value.hpp`：`Object` 自前向声明供 `DerivedFromObj` concept 用，Value↔Object 的实现依赖置于 `Value.cpp` 一侧。自由函数 `log_obj_alloc(Object*)`（DEBUG 日志：打印地址/size/`obj->type_name()`）与 `to_string(ObjType)`（`ObjType` 枚举的静态 PascalCase 映射，如 `String`/`NativeFn`/`Module`，是类型名的**单一来源**，`Object::type_name()` 委托之）。**类型名约定全项目统一 PascalCase**（原语 `Nil`/`Bool`/`Int`/`F64`/`Obj`、对象 `String`/`Function`/`NativeFn`/...）。子类型已落地 `ObjString`/`ObjFunction`（含捕获描述表 `UpvalueDesc`）/`ObjUpvalue`/`ObjClosure`（M5 增 `defining_class_`：方法闭包所属类，MAKE_METHOD 注册时 set，非方法闭包恒 nullptr，trace 补标容 nullptr）/`ObjClass`/`ObjInstance`/`ObjBoundMethod`/`ObjNativeFn`/`ObjModule`/`ObjException`。
- `object/ObjString.hpp`/`.cpp`：SSO 字符串（`kShortCapacity=15`，短串内联 / 长串 `long_chars_` 独立 buffer；`is_long()` 由 `length_ > kShortCapacity` 派生不存标志位），FNV-1a 哈希（经 `util::hash_str`）。访问器 `view()`/`length()`；`equals(const Object*)` override（先比指针 intern 命中快速路径、再比 `view()` 字符内容）；`to_string()` override 返字符内容原文（无引号，如 `hello`）。`new_string` 工厂（Phase 2 起经 GC `InternPool` 驻留：等价内容共享同一 `ObjString*`，命中不分配不 GC，未命中 `new_object` + `intern_insert`）。`new_string` 内部对 `intern_insert` 窗口**不加守卫**：`s` 虽此刻白色无根，但 `intern_insert -> InternPool::insert -> allocate<ObjString*>` 走 trivial 分配（永不触发 GC，见 `GC.hpp` 核心不变式），故 `s` 跨 insert 不会被回收。`name`/`module` 跨 `new_object` 顶部 `maybe_collect` 的守卫仍保留（那是真 GC 触发点，承重）。
- `object/ObjFunction.hpp`/`.cpp`：函数对象（`ObjFunction final : Object`，`ObjType::FUNCTION`）：持 `CodeUnit unit_` 值成员（编译器经 `unit()` 直接操作裸字段 emit）+ `ObjModule* module_`（所属模块，词法归属，构造时传入、不可变、非空；VM 据此定位「当前模块 globals」）+ `ObjString* name_`（intern 同指针；**恒非空**，ctor ASSERT 非空--入口函数名 `<main>`（主入口）/`<module>`（导入）、lambda 名 `<anonymous>`、具名函数为声明名；`<>` 是正常标识符中不可用的符号，具独特辨识度；统一「每个函数都有名字」模型）+ `u8 arity_`（参数个数，上限 255）+ `Array<UpvalueDesc> upvalue_descs_` 捕获描述表（`UpvalueDesc{bool is_local; u16 index}` 定义于头，纯标量聚合：is_local=true 捕直接外围帧局部槽 index、false 穿透复用外围闭包的第 index 个 upvalue；编译期 CodeGen 一次性 flush、运行期只读，`upvalue_descs()` 非 const + const 读口；存元数据、不进字节码流，CLOSURE 保持定长 3B；与 ObjClosure::upvalues_ 按下标一一对应；trace 不标）。访问器 `unit()`（非 const + const 重载）/`name()`/`arity()`/`module()`/`upvalue_descs()`（非 const + const 重载）。地址哈希型；`equals` 保持默认地址相等（函数无内容相等语义）；`trace()` 标 name_ + module_ + 委托 `unit_.trace`（常量池；module_ 回指形成 module<->entry 环，mark-sweep 三色标记天然破环）；`to_string()` 统一渲染 `<fn name>`（入口 `<fn <main>>`/`<fn <module>>`、lambda `<fn <anonymous>>`、具名 `<fn add>`）；工厂 `new_function(gc, module, name, arity)` **不替调用方守卫入参**（「每方只守自己创建的」），只做一次 `new_object`、无内部新建对象；调用方须在调用前自行根化 module 与 name（皆不保命：module 可能尚未入 VM 模块表、name 经 intern 是 weak root），跨 `new_object` 顶 maybe_collect。
- `object/ObjUpvalue.hpp`/`.cpp`：upvalue 对象（`ObjUpvalue final : Object`，`ObjType::UPVALUE`，非拷贝/非移动）：闭包「捕获即引用」的载体（M4）。持 `Value* location_`（open 态指入值栈槽，grow_stack_ 搬迁后经 `set_location` 重绑；closed 态恒指 `&closed_`）+ `Value closed_`（ctor 播 `nil_val`，`close()` 时迁入自持值）+ `ObjUpvalue* next_open_`（侵入式开链节点，VM 按槽址降序维护链头；**不叫 `next_`**--与基类 `Object::next_`（GC 对象链字段）撞名，`GC::new_object` 经基类字段链接会被派生字段遮蔽）。访问器 `is_open()`/`value_slot()`（open -> `location_`、closed -> `&closed_`，LOAD/STORE_UPVALUE 统一走它，非 const + const 两重载）/`next_open()`/`set_next_open()`；`close()`（`closed_ = *location_; location_ = &closed_`）；`set_location()`（重绑用，仅 open 态，debug 断言）。`trace` 标 `*value_slot()`（open 标栈槽内值 / closed 标 closed_，两态同一地址语义）；upvalue 本体从不出现在 aria 值面（语言层不可见），`to_string` 用基类默认、`format_value_debug` 的 UPVALUE 分支渲染 `<upvalue>`。工厂 `new_upvalue(gc, Value* slot)`：入参是裸栈槽地址无对象可守，只做一次 `new_object`、无内部新建；返回白色无根，调用方须立即链入 VM 开链（链上节点经 VM 根 tracer 保命）。
- `object/ObjClosure.hpp`/`.cpp`：闭包对象（`ObjClosure final : Object`，`ObjType::CLOSURE`）：函数 + 捕获数组 + defining class。持 `ObjFunction* function_`（被包函数，恒非空，ctor ASSERT；callable 收敛为闭包后，运行期一律以 `ObjClosure` 进帧，`ObjFunction` 退为常量池内部物）+ `Array<ObjUpvalue*> upvalues_`（ctor 空态，VM 执行 CLOSURE 时按 `fn->upvalue_descs()` 捕获描述表逐个后填，之后只读；与描述表按下标一一对应）+ `ObjClass* defining_class_`（M5：方法闭包所属 defining class，ctor nullptr，VM 执行 MAKE_METHOD 注册时 `set_defining_class` 一次、之后只读；非方法闭包恒 nullptr。挂闭包而非共享的 ObjFunction 常量：函数体内 def 执行 N 次产生 N 个类共用同一 fn 常量，superclass 运行期可重绑，戳共享 fn 会跨实例串错 super 链；`LOAD_SUPER_METHOD` 从 `frame.closure->defining_class()` 直读）。访问器 `function()`/`upvalues()`（const Array&）/`upvalue_count()`/`defining_class()`/`set_defining_class`；`add_upvalue(ObjUpvalue*)` 供 CLOSURE 执行期逐个后填（Array push 走 trivial 分配不触 GC，靠 GC 核心不变式免逐个守卫）。地址哈希型；`equals` 默认地址相等（同一 fn 的两次捕获是不同闭包，按身份判等）；`trace` 标 function_ + 全部 upvalue（upvalue 再各自标其槽值/闭值）+ defining_class_（容 nullptr；类静态表里的方法闭包经此级联标所属类，「静态方法闭包经 `Foo.m` 上栈时类亡指针悬垂」防线）；`to_string()` 委托 `function_->to_string()` 渲染 `<fn name>`（与纯函数同文案，trace_execution 兼容；闭包身份经 `type()`/`type_name()` 反射可见），`format_value_debug` 的 CLOSURE 分支同文案（Value.cpp，非虚路径）。工厂 `new_closure(gc, ObjFunction*)` 不替调用方守卫入参（「每方只守自己创建的」），只做一次 `new_object`、无内部新建；function_ 通常已入常量池（根），返回对象白色无根须立即发布进根。
- `object/ObjClass.hpp`/`.cpp`：类对象（`ObjClass final : Object`，`ObjType::CLASS`，M5）：def 类的运行期载体，语义模型 = 类级一张静态表 + superclass 单链（实例字段在 ObjInstance 的 fields 表，不在类上；查找序 `foo.x` 先实例 fields、未命中沿链查各类静态表）。类成员读写取 Python/JS 式**读穿透、写遮蔽**（M5 决策补记）：读沿链 fall-through；类上赋值落**接收类自身**表（继承名新建遮蔽键、本类已有原槽更新），沿链全 miss 的新名字拒（无 monkey-patch），方法槽亦允许改写--bound 缓存取首解析快照（已解析实例沿用旧绑定）、"init" 赋值同步 `init_`。持 `ObjString* name_`（类名，intern 驻留同指针，**指针恒非空**、ctor ASSERT）+ `ObjClass* superclass_`（父类，唯一 super 为 nullptr 者是 VM bootstrap 的 Object 根类；MAKE_CLASS 运行期注入、此后不可变）+ `AriaHashTable field_`（**静态变量 + 静态/实例方法同存一张表**，M5 决策 2；单数 `field_` 区分 ObjInstance 的实例字段表 `fields_`：键 intern ObjString*、值为绑定 Value，方法槽的值是 ObjClosure、静态变量槽是任意 Value，区分在值类型本身是否 CLOSURE、表内无 tag；MAKE_STATIC/MAKE_METHOD 与类上赋值写此表（写遮蔽）；惰性分配）+ `ObjClosure* init_`（构造器闭包，ctor nullptr；**MAKE_CLASS 从父类 seed + MAKE_METHOD("init") 覆盖 + 类上 init 赋值同步**三写点（决策补记：值非 ObjClosure 拒写），不变式「建成的类 init_ 非空且与类表 init 槽一致」由 VM 建类/写路径保证，call_value CLASS 实例化取用）。访问器 `name()`/`superclass()`/`field()`（非 const + const）/`init()`/`set_init`；**`find_field(ObjString*) -> Value*`**：沿 super 链查（self 起、逐父向上），命中返回表内值槽指针、未命中 nullptr--只读与存在性检查用，写遮蔽语义下写不经此槽（STORE_FIELD 类路径先经本函数全链存在性检查、再落 `upsert_field`）；super 查找（从父类起走链）同用；纯查找无分配 GC-pure；`upsert_field(ObjString*) -> Value*`：**只 upsert 本类自身表**（不沿链）--类成员写路径本体（本类已有原槽更新、继承名新建遮蔽键、父表不动），与创建路径 MAKE_STATIC/MAKE_METHOD 共用；命中保留值/未命中 V{} 零填充由调用方覆写，可能 rehash（调用方取回指针立即写、勿跨 upsert 持有）。地址哈希型；`equals` 默认地址相等（类按身份判等）；`trace` 标 name_ + superclass_（容 nullptr）+ init_（容 nullptr）+ 委托 `field_.trace(gc)`（方法闭包的 defining_class 经 ObjClosure::trace 级联）；`to_string()` 渲染 `<class Foo>`，`format_value_debug` 的 CLASS 分支同文案。工厂 `new_class(gc, ObjString* name, ObjClass* super)` 不替调用方守卫入参（「每方只守自己创建的」），只做一次 `new_object`、无内部新建；**调用方须在调用前自行根化 name 与 super**（name 经 intern 是 weak root、super 可能尚未入任何根，如 MAKE_CLASS peek-不弹栈纪律），返回对象白色无根须立即发布进根（MAKE_CLASS 原槽写回即经值栈根）。
- `object/ObjInstance.hpp`/`.cpp`：实例对象（`ObjInstance final : Object`，`ObjType::INSTANCE`，M5）：类实例化的产物（call_value CLASS 分支）。持 `ObjClass* class_`（所属类，构造注入、不可变、**恒非空** ctor ASSERT；方法派发与字段未命中沿类链查静态表的起点）+ `AriaHashTable fields_`（实例字段表：`init` 内 `this.x = ...` 落此，无字段预声明、全动态；**bound-method 缓存同居此表**（M5 决策 4，与真字段同表同 keyspace）--fields 命中优先即真字段遮蔽同名方法与缓存项，缓存三铁则见 M5 计划 §2.4；惰性分配）。访问器 `cls()`/`fields()`（非 const + const，无 setter--实例不换类）。地址哈希型；`equals` 默认地址相等（实例按身份判等）；`trace` 标 class_ + 委托 `fields_.trace(gc)`（缓存的 bound 经值级联，GC 侧零额外负担）；`to_string()` 渲染 `<Foo instance>`，`format_value_debug` 的 INSTANCE 分支同文案。工厂 `new_instance(gc, ObjClass*)`：shell 单次分配、fields 惰性 ==> **无内部二级分配、工厂内无中间 GC 点**，不替调用方守卫入参（cls 由调用方根化，实例化路径 cls 在栈）；返回对象白色无根，建成即写栈（值栈根）。
- `object/ObjBoundMethod.hpp`/`.cpp`：绑定方法对象（`ObjBoundMethod final : Object`，`ObjType::BOUND_METHOD`，M5）：方法闭包 + 绑定的接收者。`obj.m` 命中类表方法时由 LOAD_FIELD 现场绑定（new_bound_method），call_value BOUND_METHOD 分支解包进帧。持 `ObjClosure* method_`（被绑定方法闭包，**恒非空** ctor ASSERT；静态方法经 `Foo.m` 取出的是裸闭包不经本类型）+ `Value receiver_`（绑定的接收者，**Value 而非 ObjInstance\***--为将来内建类型方法（如 list.m）留泛化，当前只产 ObjInstance 接收者；call_value 解包时作实例方法帧槽 1 的 this）。访问器 `method()`/`receiver()`。地址哈希型；`equals` 默认地址相等（绑定按身份判等：同一方法绑不同实例是不同对象）；`trace` 标 method_ + `mark_value(receiver_)`（receiver 装箱任意对象，值级联）；`to_string()` 渲染 `<bound method m>`（m = method_ 的 fn 名），`format_value_debug` 的 BOUND_METHOD 分支同文案。工厂 `new_bound_method(gc, ObjClosure*, Value)` 不替调用方守卫入参，只做一次 `new_object`、无内部新建；调用方须在调用前自行根化 method 与 receiver 中的对象（LOAD_FIELD 路径 instance 仍 peek 在栈、closure 在类表内可达），返回对象白色无根须立即发布进根（LOAD_FIELD 先写回原槽根化再回填缓存）。
- `object/ObjNativeFn.hpp`/`.cpp`：原生函数对象（`ObjNativeFn final : Object`，`ObjType::NATIVE_FN`），把 C++ 函数包成 aria `Value`，供 builtins 与嵌入 API 用。签名 `using NativeFn = bool (*)(AriaVM& vm, Span<Value> slots)`：`slots[0]`=槽 0（callee/返回槽，原生函数把返回值写于此）、`slots[1..argc]`=实参（`argc=slots.size()-1`，天然变参、不存 arity，fn 自查元数）；返回 `bool`（true=成功写槽 0、false=失败），`vm.fail`/`vm.raise` 置 `Movement` 挂起错误寄存器并返回 `false`，故失败路径惯用一行 `return vm.fail(...)`。`CALL` 命中时不进帧同步直接调用，VM 以 bool 为成败信号、寄存器为错误载荷（debug 断言 `ok == !has_error()`）。详见 `.claude/reference/runtime/vm-design.md` §4.7。持 `ObjString* name_`（**恒非空**，ctor ASSERT--无具名需求者用 `kAnonymousName`（`"<anonymous>"`，定义于 `src/aria.hpp` 项目级定义头，与 ObjFunction 的 lambda 命名一致）经 `new_native_fn(gc, fn)` 匿名重载自动 intern；渲染 `<fn <anonymous>>`）+ `NativeFn fn_`（恒非空）；访问器 `name()`/`fn()`；地址哈希型；`trace` 标 name_；工厂 `new_native_fn(gc, name, fn)` **不替调用方守卫入参**，只做一次 `new_object`；调用方须在调用前自行根化 name（intern weak root），fn 为标量无需入根。匿名重载 `new_native_fn(gc, fn)` 内部 `new_string(kAnonymousName)` 驻留并自守（工厂守「自己创建的」），调用方无需根化。
- `object/ObjException.hpp`/`.cpp`：异常对象（`ObjException final : Object`，`ObjType::EXCEPTION`，非拷贝/非移动）：VM 检测到的运行时错误 / 原生函数报错的装箱载荷（M3 try/catch/throw 异常通道的运行时载体之一）。持 `ErrorCode code_`（机器标识：分类/名称经 `to_string(ErrorCode)`/`category_of` 再取，同 Error）+ `ObjString* message_`（**完整烘焙消息串**，与 `Error::message()` 同形--含 `"Category: Name"` 前缀与位置前缀（运行期装箱为 `"path:line: "`，编译期为 `path:line:col:`）；intern 驻留同指针，**恒非空**--ctor ASSERT，无消息错误以空串 intern 兜底）。**message_ 原样存调用方传入的已烘焙串、工厂不经 `make_message` 做任何加工**：烘焙发生在 raise 侧（经 `Error::make_message` 烘齐，`from_detail` 同源经它），`to_error()` 经 `Error::from_baked` 也**原样回传**（跳过 `make_message` 重烘--否则双重前缀）。位置不丢、catch 的 print(e) 渲染完整消息不退化；边界文案/测试断言与 Error 直构逐字一致（定稿见 `.claude/reference/runtime/exception-implementation-pitfalls.md` 坑 #7）。访问器 `code()`/`message()`。`to_error()`（定义在 .cpp）经 `Error::from_baked(code_, message_->view())` 还原为边界 Error（Error 自有 String，产物脱离 GC，异常本体被回收后仍可读；供测试/嵌入方断言 -- VM 未捕获出口经 `uncaught_error_parts` 直读 `code_`/`message_` 同源拆件，不中转 Error）；`trace()` 标 message_（唯一 GC 子节点）；`size()` = sizeof 壳；`to_string()` 渲染完整烘焙消息（M3 catch 的 `print(e)`/`str(e)` 显示 `"Category: Name detail"` 同款文案）。地址哈希型；`equals` 默认地址相等。工厂 `new_exception(gc, code, StringView message)` 入参是 **StringView 的已烘焙完整消息串**（如 `err.message()`/`Error::make_message` 产物）：内部 `new_string` 驻留并自行守卫跨下方 `new_object`（工厂守「自己创建的」），调用方无需手动建串根化；返回对象白色无根，须立即发布进某根（如 `ctx.raise(Value::from_obj(...))`--入寄存器后由 VM 根 tracer 标 pending_error 保命）。**注意区分**：本类承载**解释器报告的错误**；aria 语言自身 throw（M3）抛任意 Value，不限定 ObjException。
- `object/ObjModule.hpp`/`.cpp`：模块对象（`ObjModule final : Object`，`ObjType::MODULE`，非拷贝/非移动），aria 的「模块 = 命名空间」（非类），一个源文件 = 一个模块。模块的绝对文件路径（= VM 模块表查重键）由 `dir_ + name_` 合成：`dir_ + "/" + name_ + ".aria"`；切分由 `fs::module_name_and_dir` 按命中文件的绝对规范路径做：`name_` = basename 去 `.aria` 后缀（stem），`dir_` = dirname。即 `dir_` 是「模块文件所在目录」、`name_` 是「模块文件名去扩展名」--就是路径的 dirname/stem 切分（`name_` 恒为单段 stem，不支持「相对源根的多段路径」语义，不依赖源根概念）。持 `ObjString* name_`（文件名去 `.aria` 后缀/stem，intern，显示名 + 合成绝对路径用，**指针恒非空**、内容可空--ctor ASSERT，合成顶层 `<script>`/REPL 等均以非空 intern 串构造）+ `ObjString* dir_`（模块文件所在目录，intern，指针恒非空、内容可空：cwd 不可用时 `new_module` 以空串兜底）+ `ObjFunction* entry_`（模块体，顶层语句编进的 arity 0 匿名函数，主入口名 `<main>` / 导入名 `<module>`，导入时 run-once；可为 nullptr）+ `AriaHashTable globals_`（模块级绑定表，顶层 var/fun/def 的目标，`LOAD/STORE/DEF_GLOBAL` 操作此表；惰性分配）。**无加载状态字段**：加载事实源 = VM 模块表成员资格（未入表 = 未加载；入表 = 已编译待 run-once 或已跑完，run-once 与循环导入「命中即复用半初始化对象」语义均由表承载，不在对象上另设 `ModuleState` 之类的冗余第二事实源）；访问器 `name()`/`dir()`/`globals()`（非 const + const）/`entry()`/`set_entry(ObjFunction*)`。`abs_path()` 合成绝对文件路径（= VM 模块表查重键形式）：`dir_` 内容空 -> 返空串（无目录锚点）；`name_` 内容空串 -> 仅返 `dir_`；否则 `dir_ + "/" + name_ + ".aria"`（供 IMPORT 相对导入取 dirname 作基；name_/dir_ 指针恒非空，不判 nullptr）。地址哈希型；`equals` 保持默认地址相等（模块按身份判等）；`trace()` 标 name_ + dir_ + entry_ + 委托 `globals_.trace`；`to_string()` 渲染 `<module name>`（name_ 恒非空，内容空时渲染 `<module >`）。工厂 `new_module(gc, name, dir)`（显式目录，dir 指针须非空）/ `new_module(gc, name)`（无显式目录取 cwd，不可用空串兜底）/ `new_module(gc, StringView name)`（name 以 StringView 传入，工厂内部 `new_string` 驻留并自行守卫，调用方无需手动建串根化）/ `new_module(gc, StringView name, StringView dir)`（name 与 dir 均以 StringView 传入，工厂内部 `new_string` 驻留 name/dir 串并自行守卫，调用方无需根化任何入参；dir 原样 intern 调用方给的串，空串即空串锚点，**不替调用方做 cwd 退化**--需退化用 2 参 StringView 重载）**不替调用方守卫入参**：3 参 `ObjString*` 版只做一次 `new_object`，调用方须自行根化 name 与 dir；`ObjString*` 2 参版内部新建 dir_str（cwd 串）故自行守卫 dir_str（工厂守「自己创建的」），但 name 仍须调用方根化；`StringView` 两版内部新建的 name_str/dir_str 均自行守卫，调用方无需根化任何入参。
