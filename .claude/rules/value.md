# value 层模块参考

- `value/`：`USING_NANBOXING` 切换机制见 `common.hpp`（core.md）--`value/Value.hpp` 经 `#ifdef` 选 `NanBoxing.hpp`（`aria::nanboxing`）或 `TagValue.hpp`（`aria::tagvalue`），并 `using namespace` 进 `aria`。`NanBoxing::Value` 把 Nil/Bool/F64/Int/Obj 压进单个 64 位 double（int 为 i48 载荷、指针取低 48 位），`sizeof==8`；`TagValue::Value` 为 `Type` tag + union，`sizeof==16`。二者 API 一致（`from_bool`/`from_f64`/`from_int`/`from_i32`/`from_obj`/`is_*`/`as_*`/`type()`/`type_name()`）。二者均为 trivial + standard-layout（POD；`std::is_pod` 已于 C++20 移除，改用 `is_trivial_v`+`is_standard_layout_v`，各头文件 `static_assert` 把关）：默认构造 `= default` 为 trivial，默认初始化 `Value v;` 是不定值**并非 nil**，取 nil/真/假统一走工厂 `nil_val()`/`true_val()`/`false_val()`（NanBoxing 走私有 `Value(u64)` 构造；TagValue 走 `Value{}` 零填充 -> `Type::Nil`=0 即 nil，而 NanBoxing 的 `Value{}` 零填充是 f64 `0.0` 非 nil，零填充值栈时留意）。可 `memcpy`、可入 `FrameStack`。`type_name()` 有两个重载：成员 `type_name()` -> `type_name(type())`、静态 `type_name(Type)` 返类型名字面量（PascalCase：`Nil`/`Bool`/`F64`/`Int`/`Obj`，全项目统一约定）。NanBoxing 额外暴露原始位访问 `bits()`/`from_bits(u64)`（供序列化/调试，位精确比较用 `same_bits(Value)`，未装箱判定用 `is_box()`）。两者的 `from_f64` 都把任意 NaN 规范化为硬件 quiet NaN（`0x7ff8...`）--NanBoxing 免其被误判为 boxed 值，且 `===` 按位比较下 `NaN === NaN` 成立依赖两表示共同规范化，任一侧不规范即语义分叉。
- `value/AriaArray.hpp`：`AriaArray : public Array<Value>`，继承 Array 存储/接口，加 `trace(GC&)`（遍历元素 `mark_value`）。非 Object，trace 须由 owner（未来 ObjList）在 collect 调。
- `value/AriaHashTable.hpp`：`AriaHashTable : public HashTable<Value,Value,ValueHash,ValueEq>`，继承 Swiss Table 实现，加 `trace(GC&)`（`for_each_occupied` 标 key+value）。含 `ValueHash`/`ValueEq` 内联包装（仅本处用，转发到 `value_hash`/`value_identical`，后者收口于 `value/Value.hpp`/`Value.cpp`）；哈希键用 `===`（`value_identical` 严格相等：对象按引用、字符串靠 intern 同指针、int 1 与 f64 1.0 不同键）。
- `value/ObjBridge.hpp`：**Value↔Object 耦合辅助的收口头**--收「同时依赖 Value 与 Object 完整类型、必须头内定义（模板）」的辅助函数；非模板的重依赖件（`type_name(Value)`/`value_equal`/`value_hash`/`format_value` 系列等）已走「`Value.hpp` 声明 + `Value.cpp` 定义」旧路、依赖问题已解，不进此头。独立成头不常驻 `Value.hpp`：模板定义硬需 include `Object.hpp`，而该依赖只服务 runtime 层用户，不拖累被编译层（常量池）广泛 include 的 `Value.hpp`（同「不污染 `Value.hpp`」既有决策）。当前成员 `try_obj<T>(const Value&)`（`DerivedFromObj` 约束）--「守卫后使用」一步守卫：`v` 持对象且动态类型匹配返 `T*`，否则（非对象/类型不符）nullptr，= `is_obj()` + `Object::try_as<T>` 合一。供 builtin 参数守卫、异常载荷判定等（如 `len` 的 String 判定、`uncaught_error_parts` 的 ObjException 判定）。`is_callable_value(Value)`（M5，inline 自由函数）：类表成员值是否为「可调用」--闭包（CLOSURE）或原生函数（NATIVE_FN）。读路径绑定判别不走本谓词（改判 `is_method(Value)` 的 defining class 戳，见 m5 计划）；本谓词保留为可调用集合的**泛化扩展缝**（未来再扩可调用集合改本谓词即可），现行消费仅 `ObjBoundMethod` ctor ASSERT（方法值可调用守卫）。`is_method(Value)`（M5，inline 自由函数，同头）：类表成员值是否为「方法」--defining class 戳定的方法闭包，读路径（`ObjInstance::load_field`/`LOAD_SUPER_FIELD`）的绑定判别谓词，一步收「取闭包 + 查戳」两步守卫；方法承载形态的**泛化扩展缝**。
- `value/Value.hpp`/`.cpp`：值操作 `value_hash`/`value_equal`/`value_identical` 声明在此（基于 `type()`+`as_*()`，两表示都编译）。**双相等**：`value_equal`（== 内容相等，Int/F64 跨类型 IEEE 数值、Obj 调 `Object::equals` 虚函数）、`value_identical`（=== 严格相等，类型严格、f64 按位、Obj 指针）；哈希键用 `===`。辅助自由函数 `is_num(Value)`（Int 或 F64）、`is_truthy(Value)`（Lua 风格真值：仅 nil/false 为假）、`type_name(Value)`（**精确类型名**统一入口，PascalCase：原语走 `Value::type_name()` constexpr 成员、Obj 走 `obj->type_name()` 取对象子类型如 `String`/`Module`；区别于 `Value::type_name()` 成员的 constexpr 粗分类--后者 Obj 一律返 `Obj` 丢子类型；错误消息类型名打印一律用本自由函数；定义在 `Value.cpp` 需 Object 完整类型）。渲染 `format_f64(f64)`/`format_value(Value)`（PRINT / REPL 回显 / 错误渲染用，Obj 走显示位虚 `to_string()`--多数内建类型经基类默认委托 `debug_repr`，ObjString 返回原文无引号）。`format_value_debug(Value)`：**非重入**调试渲染（执行跟踪 `DEBUG_TRACE_EXECUTION` / 反汇编常量池共用），内置原语与 `format_value` 一致，Obj 走虚 **`debug_repr()`** 而非可重载的 `to_string()`（后者是未来用户类 `__str__` 的挂载点，可重载为运行 aria 字节码，`dispatch_loop` 内调试上下文调用会重入 VM 致无限递归）；`debug_repr` 的 override 契约是**纯 C++ 惰性渲染**（绝不重入 VM / 不触 GC 回收，见 `Object.hpp`），故调试上下文经虚分派调用安全；各类型 debug 文案由各子类型自己实现（逐类型形态见 `object.md`），本函数只剩一行虚调用、不按 `ObjType` 分型。原语 nil/bool/int/f64 同 `format_value`。定义在 `Value.cpp`（`<bit>`/`Object.hpp`/`util.hpp`，不再 include 任何具体子类型头）。
