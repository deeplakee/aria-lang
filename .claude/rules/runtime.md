# runtime 层模块参考

VM/执行上下文的设计与分阶段路线见 `.claude/reference/runtime/vm-design.md`；import 端到端处理见 `.claude/reference/runtime/import-handling-overview.md`，路径解析细节见 `.claude/reference/runtime/import-path-resolution.md`（均按需 Read）。

- `runtime/FrameStack.hpp`：`FrameStack<T, Capacity>` 模板--面向 trivial 帧（`CallFrame` 计划用）的栈式槽位池；零开销（`acquire`/`pop`/`truncate`/`clear`），一次分配永不扩容（指针稳定）；`truncate(n)` 供异常 unwind 跨多帧（异常记录表方案下按记录登记的深度 `truncate` 回退，无需 `ExceptionFrame` 栈）。其余公共 API：`operator[]`/`top`/`size`/`capacity`/`empty`/`span`（`span()` 返已用区间，GC trace 用）。要求 T trivial + trivially-copyable + trivially-destructible（`static_assert` 三连把关）。
- `runtime/Movement.hpp`：执行上下文（纯 C++ 类，非 Object：值栈/帧不进对象链表，改经 AriaVM 的 vm_roots tracer 在 collect 时直标，M6 协程期升级 `ObjMovement : Object` 入链表；`using VMContext = Movement` 别名）：可增长值栈（GC 分配的 `Buffer<Value>` 底座 + `top_` 裸指针，初始 `kStackInit=1024`，push 溢出 2x 增长并重定位活动帧 slots）+ `FrameStack<CallFrame, kFrameMax=256>`；值栈 `push/pop/drop/peek/stack_size/stack_capacity/stack_base/stack_top`，帧栈 `frames()/frames_full`，进/出帧 `enter_frame(fn, argc)`/`exit_frame()`（slots 与值栈对应关系收口于此；`enter_frame` 定义在 `.cpp`--需 `ObjFunction` 完整类型，`exit_frame` inline 于头文件），复用 `reset()`，挂起错误侧信道 `raise/has_error/take_error/clear_error`（`Opt<Error> pending_error_` 寄存器，供原生函数等冷路径报错）。`CallFrame`（trivially-copyable 聚合，同文件）：`function`（M1-M3 持 `ObjFunction*`，M4 换闭包）+ `unit`（缓存 `CodeUnit*`）+ `module`（缓存 `ObjModule*`，供 `LOAD/STORE/DEF_GLOBAL` 定位模块 globals）+ `ip`（裸指针）+ `slots`（局部基址，callee 在槽 0、参数从槽 1 起）。
- `runtime/AriaVM.hpp`/`.cpp`：解释器（M1 已落地，M2 进行中）。`run()` 返 `Result<Value, Error>`（成功=返回值，失败=未捕获运行时错误；M6 协程挂起将扩三态含 `Yielded`）。`run(ObjFunction*)`：reset 主上下文 + 源根入口槽 `[0]` 原地替换为入口模块 `root_` + 压 callee/主帧 -> `run_()` 主循环 -> 结束再 `reset()`（清空值栈/帧，避免 run() 外 GC 经 tracer 标到陈旧栈值）。**GC 已启用**：值栈 `[base, top)` + 各活动帧 `function`/`module` 经 VM 根 tracer 标根（见下），`IMPORT`/`DEF_GLOBAL` 等已按「栈即根」前置编写（peek-not-pop）。`IMPORT` 取到模块对象后 `ctx.push(module)` 压栈（不再自绑 globals，绑定交 CodeGen 按 `DEF_GLOBAL`/值填槽走）；`module` 经 `modules_` 根可达，非移动 GC 故 push（栈溢出增长走 Buffer 重分配）期间指针稳定，**不加守卫**，入栈后另经值栈根可达。。`JUMP_BACK`（循环回边）为 safe point 调 `gc_.maybe_collect()`。指令子集：常量/字面量（`LOAD_CONST`/`LOAD_IMM`/`LOAD_NIL`/`LOAD_TRUE`/`LOAD_FALSE`）、局部槽（`LOAD/STORE_LOCAL` + `_L` 长变体，peek-store）、**全局**（`DEF/LOAD/STORE_GLOBAL`：按名查/写当前模块 `globals`，`DEF` upsert 创建、`LOAD/STORE` 未定义报 `UndefinedVariable`）、算术/比较（`numeric_op`：双 Int 走整数路径、任一 F64 升浮点；int 除/模零报错、f64 按 IEEE）、相等（`EQUAL/NOT_EQUAL` 走 `value_equal`、`STRICT_EQUAL/STRICT_NOT_EQUAL` 走 `value_identical`）、`NOT/NEGATE`、栈操作（`POP`/`POP_N`/`DUP`/`DUP2`）、`JUMP*`（u16，方向在 opcode，偏移以读完操作数后 ip 为基准；含 `JUMP_TRUE_OR_POP`/`JUMP_FALSE_OR_POP` 短路）、`CALL`（`ObjFunction` 进帧查 arity/帧溢出 + `ObjNativeFn` 同步调用，见 `vm-design.md` §4.7；`call_value` 分发到 `call_function`（arity/帧溢出检查 + 进帧）与 `call_native`（同步调用 + 侧信道错误 `take_error` 处理））、`RETURN`（弹 callee 残留 + 压返回值，帧空即返回成功）、`HALT/PRINT/NOP`、**`IMPORT`（部分落地）**：经 `resolve_module` 解析 specifier 为绝对规范路径（模块表键）-> `new_string` intern -> `modules_` 查表，命中复用模块对象并 `ctx.push` 压栈（`IMPORT path:u16`，栈效应 `... -> [module]`；绑定交 CodeGen 按 `DEF_GLOBAL`（顶层）/ 值填槽 + `mark_initialized`（嵌套）走）；两条失败路径均报 `ModuleNotFound`--`resolve_module` 返 `nullopt`（无源根命中，"no matching source root"）或文件解析命中但模块未入表（"loading not implemented yet"，磁盘加载 + AST->CodeUnit 编译 + run-once 链路未就绪，见 `import-handling-overview.md`/`import-path-resolution.md`）。范围外指令 `not_implemented` 经 `fatal_error` 终止（坏 opcode 走 `UNREACHABLE`）。真值 Lua 风格（仅 nil/false 假）。**注意**：函数序言须先压 nil 预留局部区（见指令集文档 §4.3），否则临时值覆写槽 1。**M2 共享状态**：自有 `GC gc_`（值成员，每 VM 一个）+ 主上下文 `main_ctx_` + 模块表 `modules_`（`AriaHashTable`，键=规范路径 `ObjString*` intern、值=`ObjModule*`，均装箱为 `Value`）+ 源根列表 `source_roots_`（`List<String>`，`[0]`=入口槽 cwd 占位/run() 换入口 root_、`[1..]`=配置根 stdlib/-L，`set_source_roots` 覆盖 `[1..]`）。构造时把 VM 根 tracer 经 `gc_.set_vm_roots` 注册进自有 GC（组合而非继承：GC 不识 VM 类型），collect 时标三类根：① `modules_`（进而 trace 各模块 name_/root_/entry_/globals_）；② `main_ctx_` 值栈 `[base, top)` 全部 Value（run() 期局部/实参/临时值只活在栈上，是最关键的根；run() 外 main_ctx_ 为空态，遍历为空）；③ 各活动帧 `function`/`module`（本可经 module -> entry -> 常量池链可达，直标更稳）。open upvalues 留待 M4。以 tracer 直标代替 Movement 升 Object（M6 协程期再升级 `ObjMovement : Object` 入对象链表）；`raise/fail` 转发到 `main_ctx_` 挂起错误寄存器（供原生函数一行报错 `return vm.fail(...);`）。公共访问器 `gc()`/`main_context()`/`modules()`/`source_roots()` 暴露上述共享状态供原生函数与测试用。

## VM 异常通道（throw/catch）落地状态

aria 语言的 `throw/catch` 与 VM 检测到的运行时错误统一走 VM 自管机制（不引入 `SETUP_EXCEPT`/`END_EXCEPT`，不依赖 C++ 异常）：`op` 返回失败 `Error` 后 `run()` 调 `raise` -> 查 CodeUnit 内异常记录表定位最近覆盖当前 `ip` 的 `try` 记录，按记录登记的帧/栈深度 `truncate` 回退（unwind），跳到对应 handler。

- **已就绪**：`OpCode::THROW`（`bytecode/code.hpp`）、`FrameStack::truncate`（供 unwind 跨帧，`runtime/FrameStack.hpp`）、`CallFrame`（`runtime/Movement.hpp`）、`AriaVM::run()`（M1 主循环）、`CodeUnit::try_records` + `find_try_handler`（异常记录表 + 按 `ip` 二分查表，`bytecode/CodeUnit.hpp`）、`raise` 的 M1 最小切片（`Movement::pending_error_` 挂起错误寄存器 + `AriaVM::raise/fail`，供原生函数侧信道报错，见 `vm-design.md` §4.7）。
- **尚未实现**：`TryRecord` 扩字段（`stack_depth`/`frame_depth`/`catch_slot`，M3 补）、完整 `raise`（查表 + `truncate` unwind + 跳 handler）、`THROW` 的运行时语义。
