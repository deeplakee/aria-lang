# runtime 层模块参考

VM/执行上下文的设计与分阶段路线见 `.claude/reference/runtime/vm-design.md`；import 端到端处理见 `.claude/reference/runtime/import-handling-overview.md`，路径解析细节见 `.claude/reference/runtime/import-path-resolution.md`（均按需 Read）。

- `runtime/FrameStack.hpp`：`FrameStack<T, Capacity>` 模板--面向 trivial 帧（`CallFrame` 计划用）的栈式槽位池；零开销（`acquire`/`pop`/`truncate`/`clear`），一次分配永不扩容（指针稳定）；`truncate(n)` 供异常 unwind 跨多帧（异常记录表方案下按记录登记的深度 `truncate` 回退，无需 `ExceptionFrame` 栈）。其余公共 API：`operator[]`/`top`/`size`/`capacity`/`empty`/`span`（`span()` 返已用区间，GC trace 用）。要求 T trivial + trivially-copyable + trivially-destructible（`static_assert` 三连把关）。
- `runtime/Movement.hpp`：执行上下文（纯 C++ 类，非 Object：值栈/帧不进对象链表，改经 AriaVM 的 vm_roots tracer 在 collect 时直标，M6 协程期升级 `ObjMovement : Object` 入链表；`using VMContext = Movement` 别名）：可增长值栈（GC 分配的 `Buffer<Value>` 底座 + `top_` 裸指针，初始 `kStackInit=1024`，push 溢出 2x 增长并重定位活动帧 slots）+ `FrameStack<CallFrame, kFrameMax=256>`；值栈 `push/pop/drop/peek/stack_size/stack_capacity/stack_base/stack_top`，帧栈 `frames()/frames_full`，进/出帧 `enter_frame(fn, argc)`/`exit_frame()`（slots 与值栈对应关系收口于此；`enter_frame` 定义在 `.cpp`--需 `ObjFunction` 完整类型，`exit_frame` inline 于头文件），复用 `reset()`，挂起错误侧信道 `raise/has_error/take_error/clear_error`（`Opt<Error> pending_error_` 寄存器，供原生函数等冷路径报错）。`CallFrame`（trivially-copyable 聚合，同文件）：`function`（M1-M3 持 `ObjFunction*`，M4 换闭包）+ `unit`（缓存 `CodeUnit*`）+ `module`（缓存 `ObjModule*`，供 `LOAD/STORE/DEF_GLOBAL` 定位模块 globals）+ `ip`（裸指针）+ `slots`（局部基址，callee 在槽 0、参数从槽 1 起）。模块体 run-once 帧不另设标志位，RETURN 按函数名 == `<module>` 判定（导入模块入口名固定，用户代码无法产生含 `<>` 的名字；见 AriaVM.cpp 匿名 `kModuleName`）。
- `runtime/AriaVM.hpp`/`.cpp`：解释器（M1 已落地，M2 进行中）。`run()` 返 `Result<Value, Error>`（成功=返回值，失败=未捕获运行时错误；M6 协程挂起将扩三态含 `Yielded`）。两个执行入口：`run(ObjFunction*)`（执行已编译函数）与 `run(SourceFile& source, ObjModule& module)`（**编译并执行**：经 `Compiler{gc_}` 把 `source` 编进 `module` 的入口 `ObjFunction`，编译失败原样透传首错 `Error`，成功即委托 `run(ObjFunction*)`；`Compiler` 每次就地构造，`source` 须存活到 `compile()` 返回（编译期 `Error` 构造时烘位置串需 `SourceFile` 存活）；`Error` 构造后自有位置串、不再持 `SourceLoc`/`SourceFile*`，故 `run()` 返回后 `source` 即可释放，`module` 由调用方提供身份、编译期由 `CodeGen::compile` 内部 `make_guard` 根化）。另有两个 **turnkey interpret 入口**返回 `InterpretResult` 枚举（`Ok`/`CompileError`/`RuntimeError`/`LoadError`，对齐 clox）：`interpret_from_src(StringView src)`（构造 `SourceFile` 名 `<script>` + 合成入口模块 `<script>`/cwd）、`interpret_from_path(StringView path)`（`SourceFile::from_path` 读盘，失败返 `LoadError`；按路径派生模块身份经 `fs::module_name_and_dir` 拆为 name=basename 去 `.aria`、dir=dirname(absolute(path))，`name` 为空（路径非合法文件模块）亦返 `LoadError`）。interpret 内部把错误渲染到 stderr 后只回类别--`Error` 已自有位置串、与 `SourceFile` 解耦，turnkey 入口内部构造/读盘的 `SourceFile` 即便返回后销毁也不影响已渲染的 `Error`，无悬垂问题，故无需 VM 源注册表；共用私有 `interpret_run(SourceFile&, ObjModule&)` 调 `run` + 按错误大类（Syntax/Semantic -> CompileError、余 -> RuntimeError）映射。`run(ObjFunction*)`：reset 主上下文 + 源根入口槽 `[0]` 原地替换为入口模块 `dir_` + 压 callee/主帧 -> `run_()` 主循环 -> 结束再 `reset()`（清空值栈/帧，避免 run() 外 GC 经 tracer 标到陈旧栈值）。**GC 已启用**：值栈 `[base, top)` + 各活动帧 `function`/`module` 经 VM 根 tracer 标根（见下），`IMPORT`/`DEF_GLOBAL` 等已按「栈即根」前置编写（peek-not-pop）。`IMPORT` 取到模块对象后 `ctx.push(module)` 压栈（不再自绑 globals，绑定交 CodeGen 按 `DEF_GLOBAL`/值填槽走）；`module` 经 `modules_` 根可达，非移动 GC 故 push（栈溢出增长走 Buffer 重分配）期间指针稳定，**不加守卫**，入栈后另经值栈根可达。`JUMP_BACK`（循环回边）为 safe point 调 `gc_.maybe_collect()`。指令子集：常量/字面量（`LOAD_CONST`/`LOAD_IMM`/`LOAD_NIL`/`LOAD_TRUE`/`LOAD_FALSE`）、局部槽（`LOAD/STORE_LOCAL` + `_L` 长变体，peek-store）、**全局**（`DEF/LOAD/STORE_GLOBAL`：按名查/写当前模块 `globals`，`DEF` upsert 创建、`LOAD/STORE` 未定义报 `UndefinedVariable`）、算术/比较（`numeric_op`：双 Int 走整数路径、任一 F64 升浮点；int 除/模零报错、f64 按 IEEE）、相等（`EQUAL/NOT_EQUAL` 走 `value_equal`、`STRICT_EQUAL/STRICT_NOT_EQUAL` 走 `value_identical`）、`NOT/NEGATE`、栈操作（`POP`/`POP_N`/`DUP`/`DUP2`）、`JUMP*`（u16，方向在 opcode，偏移以读完操作数后 ip 为基准；含 `JUMP_TRUE_OR_POP`/`JUMP_FALSE_OR_POP` 短路）、`CALL`（`ObjFunction` 进帧查 arity/帧溢出 + `ObjNativeFn` 同步调用，见 `vm-design.md` §4.7；`call_value`/`call_function`/`call_native` 均返 `bool` 成败信号 -- 失败时错误载荷已 raise 进 `ctx` 挂起错误寄存器、调用方据 `bool` 取 `take_error` 沿 `runtime_err` 传播，`call_value` 分发到 `call_function`（arity/帧溢出检查 + 进帧）与 `call_native`（同步调用，失败载荷留寄存器交调用方取出，不在本函数 `take_error`））、`RETURN`（弹返回值 + `exit_frame`；顶层主帧返回即返回程序结果，模块体帧（按函数名 == `<module>` 判定）则弹弃返回值、置该模块 `Loaded`、改压模块对象）、`HALT/PRINT/NOP`、**`IMPORT`（已落地）**：经 `resolve_module` 解析 specifier 为绝对规范路径（模块表键）-> `new_string` intern -> `modules_` 查表（`IMPORT path:u16`，栈效应 `... -> [module]`；绑定交 CodeGen 按 `DEF_GLOBAL`（顶层）/ 值填槽 + `mark_initialized`（嵌套）走）。命中(Loading 半初始化/Loaded 完整)复用并 `ctx.push` 压栈；未命中调 `load_module` 得模块(Loading)，以其 `entry`(<module>)作**普通 0 参函数调用**进帧(`call_value`)后 break -- 模块体 run-once 即执行一个函数,由主循环照常驱动,其 RETURN 按函数名 == `<module>` 判定模块体帧,弹弃返回值、置 `Loaded`、压回模块对象(模块体「返回模块」),故命中/未命中栈效应统一 `[..., module]`，无递归 `run_()`；解析失败(`resolve_module` 返 `nullopt`)报 `ModuleNotFound`。**`load_module(canonical_path, import_specifier)`**（IMPORT 未命中分支的加载层，私有成员，**仅加载与编译**；`canonical_path` = 命中文件的绝对规范路径 intern `ObjString*`，一身二任：既作 `modules_` 表键又作读盘路径；`import_specifier` = 用户写的原始 import 串，仅报错用）：`SourceFile::from_path(canonical_path->view())` 读盘 -> `fs::module_name_and_dir` 派生身份 {name=stem, dir=dirname}（同入口约定，`abs_path()` 还原 canonical key）-> `new_module`(Loading)+`make_guard` -> `modules_.upsert` 入表占位(供循环导入命中半初始化) -> `Compiler{gc_}.compile(source, module, kModuleName)` 编译(入口名 `<module>`，`set_entry`，编译期 Error 含被导入文件位置原样透传) -> 返回模块(Loading，待 run-once 置 Loaded)。读盘失败/name 空报 `ModuleNotFound`。**模块体帧判定**：不在 `CallFrame` 上设标志位,RETURN 按函数名 == `<module>`（匿名 `kModuleName`）识别 IMPORT 加载层驱动的模块体 run-once 帧 -- 导入模块入口名固定为 `<module>`，主入口为 `<main>`，用户代码无法产生含 `<>` 的名字，故函数名即唯一判据,无需进帧时置位/复位,亦无帧槽复用残留之虞。**根安全**：`canonical_path`(intern weak root)经 IMPORT case 的 `canonical_path_guard` 跨 `find`/`load_module` 内 `upsert`(rehash 触 GC)根化；`module`/`entry` 经 `modules_`+`module->entry_` 根可达，非移动 GC 故 `ctx.push` 期间指针稳定。`load_module` 见 `import-handling-overview.md`/`import-path-resolution.md`。范围外指令 `not_implemented` 经 `fatal_error` 终止（坏 opcode 走 `UNREACHABLE`）。真值 Lua 风格（仅 nil/false 假）。**注意**：函数序言须先压 nil 预留局部区（见指令集文档 §4.3），否则临时值覆写槽 1。**M2 共享状态**：自有 `GC gc_`（值成员，每 VM 一个）+ 主上下文 `main_ctx_` + 模块表 `modules_`（`AriaHashTable`，键=规范路径 `ObjString*` intern、值=`ObjModule*`，均装箱为 `Value`）+ 源根列表 `source_roots_`（`List<String>`，`[0]`=入口槽 cwd 占位/run() 换入口 dir_、`[1..]`=配置根 stdlib/-L，`set_source_roots` 覆盖 `[1..]`）。构造时把 VM 根 tracer 经 `gc_.set_vm_roots` 注册进自有 GC（组合而非继承：GC 不识 VM 类型），collect 时标三类根：① `modules_`（进而 trace 各模块 name_/dir_/entry_/globals_）；② `main_ctx_` 值栈 `[base, top)` 全部 Value（run() 期局部/实参/临时值只活在栈上，是最关键的根；run() 外 main_ctx_ 为空态，遍历为空）；③ 各活动帧 `function`/`module`（本可经 module -> entry -> 常量池链可达，直标更稳）。open upvalues 留待 M4。以 tracer 直标代替 Movement 升 Object（M6 协程期再升级 `ObjMovement : Object` 入对象链表）；`raise/fail` 转发到 `main_ctx_` 挂起错误寄存器（供原生函数一行报错 `return vm.fail(...);`）。公共访问器 `gc()`/`main_context()`/`modules()`/`source_roots()` 暴露上述共享状态供原生函数与测试用。**执行跟踪**：`DEBUG_TRACE_EXECUTION` 宏（CMake `ARIA_DEBUG_TRACE_EXECUTION` option，OFF 默认，对齐 `ARIA_DEBUG_GC`/`ARIA_DEBUG_PRINT_CODE` 配置法）控制是否在每条指令执行前打印执行状态--`run_` 主循环顶取 opcode 前（此时 `frame.ip` 指向待执行指令）调匿名命名空间 `trace_execution(ctx)`，经 `Disassembler::disassembleInstruction(frame.unit, ip_off)`（仅读不推进 VM 的 ip）解码当前指令，三行输出到 stderr（与 GC 调试日志/`DEBUG_PRINT_COMPILED_CODE` 同走 stderr，与 `PRINT` 的 stdout 分流）：① 字节码行 `[trace] <module name> Loading|Loaded  <fn名> @ip偏移 指令反汇编`（模块信息 to_string + state 置于 `[trace]` 与 `<fn>` 之间，第一行即含完整位置上下文 模块/函数/ip/字节码，无需下扫模块行）；② 栈行 `stack[n]: [ v1 ][ v2 ]...`（值栈 `[base, top)` 全部 Value 经**非重入**的 `format_value_debug` 渲染，空栈 `(empty)`）+ 其下方一行帧栈底标记 `^ frame[i]`（`^` 对齐到当前帧 bottom 槽 `[` 下标，bottom = slots 基址在值栈中的偏移，联动指示栈中哪一段是当前帧的局部区；fn/ip 已在字节码行不重复，故帧信息只留栈底位置 + frame 索引）。**`format_value_debug` 不用 `format_value`**：后者对 Obj 走可重载的虚 `Object::to_string()`，未来用户类（M5）可重载其运行 aria 字节码，trace 在 `run_` 内逐指令调用会重入 VM 致无限递归；故 `format_value_debug` 对 Obj 走**非虚**的 `obj->type()` 枚举分派--已知内置类型（ObjString/ObjFunction/ObjModule/ObjNativeFn）经纯 C++ 访问器渲染（同各自 `to_string` 文案；字符串走 `format_string` 带引号），其余（未来用户实例 / 未落地类型）退化为 `<Type at 0xaddr>`（同 `Object::to_string` 基类默认但静态构造、不经虚分派），绝不触用户重载。原语 nil/bool/int/f64 同 `format_value` 无重入风险。字节码行的 `frame.function->to_string()`/`mod->to_string()` 为 ObjFunction/ObjModule（内置纯 C++，用户无法重载），无重入风险。关闭时 `#ifdef` 包裹零开销。

## VM 异常通道（throw/catch）落地状态

aria 语言的 `throw/catch` 与 VM 检测到的运行时错误统一走 VM 自管机制（不引入 `SETUP_EXCEPT`/`END_EXCEPT`，不依赖 C++ 异常）：`op` 返回失败 `Error` 后 `run()` 调 `raise` -> 查 CodeUnit 内异常记录表定位最近覆盖当前 `ip` 的 `try` 记录，按记录登记的帧/栈深度 `truncate` 回退（unwind），跳到对应 handler。

- **已就绪**：`OpCode::THROW`（`bytecode/code.hpp`）、`FrameStack::truncate`（供 unwind 跨帧，`runtime/FrameStack.hpp`）、`CallFrame`（`runtime/Movement.hpp`）、`AriaVM::run()`（M1 主循环）、`CodeUnit::try_records` + `find_try_handler`（异常记录表 + 按 `ip` 二分查表，`bytecode/CodeUnit.hpp`）、`raise` 的 M1 最小切片（`Movement::pending_error_` 挂起错误寄存器 + `AriaVM::raise/fail`，供原生函数侧信道报错，见 `vm-design.md` §4.7）。
- **尚未实现**：`TryRecord` 扩字段（`stack_depth`/`frame_depth`/`catch_slot`，M3 补）、完整 `raise`（查表 + `truncate` unwind + 跳 handler）、`THROW` 的运行时语义。
