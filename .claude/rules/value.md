# value 层模块参考

- `value/`：`src/common.hpp`（项目级公共头）中 `#define USING_NANBOXING`（当前始终开启）-> `value/Value.hpp` 经 `#ifdef` 选 `NanBoxing.hpp`（`aria::nanboxing`）或 `TagValue.hpp`（`aria::tagvalue`），并 `using namespace` 进 `aria`。`NanBoxing::Value` 把 Nil/Bool/F64/Int/Obj 压进单个 64 位 double（int 为 i48 载荷、指针取低 48 位），`sizeof==8`；`TagValue::Value` 为 `Type` tag + union，`sizeof==16`。二者 API 一致（`from_bool`/`from_f64`/`from_int`/`from_i32`/`from_obj`/`is_*`/`as_*`/`type()`/`type_name()`）。二者均为 trivial + standard-layout（POD；`std::is_pod` 已于 C++20 移除，改用 `is_trivial_v`+`is_standard_layout_v`，各头文件 `static_assert` 把关）：默认构造 `= default` 为 trivial，默认初始化 `Value v;` 是不定值**并非 nil**，取 nil/真/假统一走工厂 `nil_val()`/`true_val()`/`false_val()`（NanBoxing 走私有 `Value(u64)` 构造；TagValue 走 `Value{}` 零填充 -> `Type::Nil`=0 即 nil，而 NanBoxing 的 `Value{}` 零填充是 f64 `0.0` 非 nil，零填充值栈时留意）。可 `memcpy`、可入 `FrameStack`。`type_name()` 有两个重载：成员 `type_name()` -> `type_name(type())`、静态 `type_name(Type)` 返类型名字面量（PascalCase：`Nil`/`Bool`/`F64`/`Int`/`Obj`，全项目统一约定）。NanBoxing 额外暴露原始位访问 `bits()`/`from_bits(u64)`（供序列化/调试，位精确比较用 `same_bits(Value)`，未装箱判定用 `is_box()`）。两者的 `from_f64` 都把任意 NaN 规范化为硬件 quiet NaN（`0x7ff8...`）--NanBoxing 免其被误判为 boxed 值，且 `===` 按位比较下 `NaN === NaN` 成立依赖两表示共同规范化，任一侧不规范即语义分叉。
- `value/AriaArray.hpp`：`AriaArray : public Array<Value>`，继承 Array 存储/接口，加 `trace(GC&)`（遍历元素 `mark_value`）。非 Object，trace 须由 owner（未来 ObjList）在 collect 调。
- `value/AriaHashTable.hpp`：`AriaHashTable : public HashTable<Value,Value,ValueHash,ValueEq>`，继承 Swiss Table 实现，加 `trace(GC&)`（`for_each_occupied` 标 key+value）。含 `ValueHash`/`ValueEq` 内联包装（仅本处用，转发到 `value_hash`/`value_identical`，后者收口于 `value/Value.hpp`/`Value.cpp`）；哈希键用 `===`（`value_identical` 严格相等：对象按引用、字符串靠 intern 同指针、int 1 与 f64 1.0 不同键）。
- `value/ObjBridge.hpp`：**Value↔Object 耦合辅助的收口头**——收「同时依赖 Value 与 Object 完整类型、必须头内定义（模板）」的辅助函数；非模板的重依赖件（`type_name(Value)`/`value_equal`/`value_hash`/`format_value` 系列等）已走「`Value.hpp` 声明 + `Value.cpp` 定义」旧路、依赖问题已解，不进此头。独立成头不常驻 `Value.hpp`：模板定义硬需 include `Object.hpp`，而该依赖只服务 runtime 层用户，不拖累被编译层（常量池）广泛 include 的 `Value.hpp`（同「不污染 `Value.hpp`」既有决策）。当前成员 `try_obj<T>(const Value&)`（`DerivedFromObj` 约束）--「守卫后使用」一步守卫：`v` 持对象且动态类型匹配返 `T*`，否则（非对象/类型不符）nullptr，= `is_obj()` + `Object::try_as<T>` 合一。供 builtin 参数守卫、异常载荷判定等（如 `len` 的 String 判定、`uncaught_error_parts` 的 ObjException 判定）。
- `value/Value.hpp`/`.cpp`：`Value.hpp` 经 `USING_NANBOXING` 选 `NanBoxing.hpp`/`TagValue.hpp` 并 `using namespace`；值操作 `value_hash`/`value_equal`/`value_identical` 声明在此（基于 `type()`+`as_*()`，两表示都编译）。**双相等**：`value_equal`（== 内容相等，Int/F64 跨类型 IEEE 数值、Obj 调 `Object::equals` 虚函数）、`value_identical`（=== 严格相等，类型严格、f64 按位、Obj 指针）；哈希键用 `===`。辅助自由函数 `is_num(Value)`（Int 或 F64）、`is_truthy(Value)`（Lua 风格真值：仅 nil/false 为假）、`type_name(Value)`（**精确类型名**统一入口，PascalCase：原语走 `Value::type_name()` constexpr 成员、Obj 走 `obj->type_name()` 取对象子类型如 `String`/`Module`；区别于 `Value::type_name()` 成员的 constexpr 粗分类--后者 Obj 一律返 `Obj` 丢子类型；错误消息类型名打印一律用本自由函数；定义在 `Value.cpp` 需 Object 完整类型）。渲染 `format_f64(f64)`/`format_string(const ObjString*)`（带引号转义）/`format_value(Value)`（PRINT / 错误渲染用，区别于反汇编的字面量形式）。`format_value_debug(Value)`：**非重入**调试渲染（执行跟踪 `DEBUG_TRACE_EXECUTION` / 反汇编常量池共用），与 `format_value` 对内置类型输出一致，但 Obj **不经可重载虚 `to_string()`**（未来用户类可重载其运行 aria 字节码，调试上下文在 `run_` 内调用会重入 VM 致无限递归），改走**非虚**的 `obj->type()` 枚举分派--已知内置类型（ObjString 走 `format_string` 带引号；ObjFunction/ObjModule/ObjNativeFn 同各自 `to_string` 文案；ObjException 走纯 C++ 访问器渲染完整烘焙消息、不带引号）经纯 C++ 访问器渲染，其余（未来用户实例 / 未落地类型）退化为 `<Type at 0xaddr>`，复用 `Object::debug_repr()`（非虚、不经虚分派，同 `to_string` 基类默认渲染但静态构造）。原语 nil/bool/int/f64 同 `format_value`。定义在 `Value.cpp`（`<bit>`/`Object.hpp`/`ObjException.hpp`/`ObjFunction.hpp`/`ObjModule.hpp`/`ObjNativeFn.hpp` 置于此，不污染 `Value.hpp`）。
