# runtime 层模块参考

VM/执行上下文的设计与分阶段路线见 `.claude/reference/runtime/vm-design.md`；import 端到端处理见 `.claude/reference/runtime/import-handling-overview.md`，路径解析细节见 `.claude/reference/runtime/import-path-resolution.md`；M3 异常（try/catch/throw）的踩坑归档与对策见 `.claude/reference/runtime/exception-implementation-pitfalls.md`（已落地；finally 已裁撤、后继 defer 已降为可选后续，异常相关特性重启前重读）（均按需 Read）。

- `runtime/FrameStack.hpp`：`FrameStack<T, Capacity>` 模板--面向 trivial 帧（`CallFrame`）的栈式槽位池；零开销（`acquire`/`pop`/`truncate`/`clear`），一次分配永不扩容（指针稳定）；`truncate(n)` 供异常 unwind 跨多帧（按异常记录表登记的深度 `truncate` 回退）。其余公共 API：`operator[]`/`top`/`size`/`capacity`/`empty`/`span`（`span()` 返已用区间，GC trace 用）。要求 T trivial + trivially-copyable + trivially-destructible（`static_assert` 三连把关）。
- `runtime/Movement.hpp`：执行上下文（纯 C++ 类，非 Object：值栈/帧不进对象链表，改经 AriaVM 的 vm_roots tracer 在 collect 时直标，M6 协程期升级 `ObjMovement : Object` 入链表；`using VMContext = Movement` 别名）：可增长值栈（GC 分配的 `Buffer<Value>` 底座 + `top_` 裸指针，初始 `kStackInit=1024`，push 溢出 2x 增长并重定位活动帧 slots 与 open upvalue 链 location_）+ `FrameStack<CallFrame, kFrameMax=256>` + open upvalue 开链头 `open_upvalues_`（M4 落地：按槽址降序的侵入式单链，链上节点经 VM 根 tracer 标根）；值栈 `push/pop/drop/peek/truncate_stack/stack_size/stack_capacity/stack_base/stack_top`（`truncate_stack(new_size)` 断言 `<= stack_size` 后置 `top_ = base + new_size`，M3 异常 unwind 命中 handler 的帧内回退入口，与 `FrameStack::truncate` 组成 unwind 完整回退），帧栈 `frames()/frames_full`，进/出帧 `enter_frame(closure, argc)`/`exit_frame()`（slots 与值栈对应关系收口于此；`exit_frame` 内置 `close_upvalues(frame.slots)` 一体收口 弹帧+关本帧区间开指+复位；`enter_frame` 定义在 `.cpp`--需 `ObjClosure` 完整类型，`exit_frame` inline 于头文件），**开链收口**（M4 落地，定义在 `.cpp`）：`capture_upvalue(slot)`（捕获单点，**单趟**同时完成复用判定与降序插链：沿降序链走到首个槽址 <= slot 的节点即停，等值即复用（同槽同局部一份引用，「捕获即引用」内外层共享同一 ObjUpvalue），更小/链尾则经**调用方传入的 GC** `new_upvalue` 建新插链（Movement 不自持分配器创建对象，分配语义归 VM 驱动）；建新到插链间无分配点，入链即经 tracer 根化；即使不变式被破出现同槽双节点也命中复用而非再插（自愈））/`close_upvalues(from)`（闭所有 `location >= from`：迁值 close + 整段摘链，降序不变式下恒为链头前缀）+ 只读链头 `open_upvalues()`（tracer 遍历标根用），`reset()` 先 `close_upvalues(buf_.data())` 再清场（HALT 收场不弹帧的安全网，防开指跨 run 复用栈区读脏值），协程 resume 链字段 `previous_`（`previous()`/`set_previous()`；M6 前置落地 -- 主上下文恒 nullptr 链尾，VM 根 tracer 自 current_ 沿链逐个标根，「resume/yield 严格成对、链尾恒 main_ctx_」的切换纪律由 tracer 链尾断言锁定；M6 前链长恒 1；**M6 定稿单循环切换模型后** previous_ 对齐 Wren caller 语义（yield/完成解链、允许再 resume），链尾断言退役（执行链遍历保留 -- main_ctx_ 不入堆，运行中协程经链覆盖；挂起协程已解链、走对象图），见 vm-design.md §4.9），挂起错误寄存器 `raise/has_error/take_error/clear_error`（`Opt<Value> pending_error_`，M3 起为运行期异常主通道寄存器（单寄存器模型，见 `.claude/reference/runtime/exception-implementation-pitfalls.md` 坑 #7）：VM 检测错误/原生报错装箱 `ObjException`{码+完整烘焙消息} 后写入、用户 `throw` 写原值；`raise(Value)` 收已构造好的载荷，构造（需分配）在持 GC 的调用方完成；只读访问器 `pending_error()` 供 VM 根 tracer 标根，置入寄存器到 take 之间跨安全点分配不回收）。`CallFrame`（trivially-copyable 聚合，同文件）：`closure`（M4 起持 `ObjClosure*`，callable 收敛为闭包、顶层入口也闭包）+ `unit`（缓存 `closure->function()->unit()`，省每条指令一跳）+ `module`（缓存 `closure->function()->module()`，供 `LOAD/STORE/DEF_GLOBAL` 定位模块 globals）+ `ip`（裸指针）+ `slots`（局部基址，callee 在槽 0、参数从槽 1 起）+ `last_ip`（u8*，本帧最近取指指令的起始指针，主循环取指前写/`init_frame_` 置 code 起始；运行期报错定位行号与 unwind 查表共用锚点，查表时按 `last_ip - unit->code.data()` 反推 offset（前提：帧存活期间 code 缓冲恒定 -- 非移动 GC + 执行期零 emit），无 NSDMI 保 trivial 聚合）。模块体 run-once 帧不另设标志位，RETURN 按函数名 == `<module>` 判定（导入模块入口名固定，用户代码无法产生含 `<>` 的名字；`kModuleEntryName`，见 `aria.hpp`）。`grow_stack_` 三类指针重绑（定义在 .cpp，链重绑解引用 ObjUpvalue 需完整类型，与 enter_frame 同理不内联于头）：搬运**前**记相对 old_base 的整数偏移（top_ / 各帧 slots 走栈内定长数组；开链 location_ 节数不定，走 `List<usize>` 暂存（GC 自身 scratch 同款 List；链序两趟间稳定，免数节点一趟）），搬运**后** `new_base + 偏移` 重建，从不触碰 dangling 指针（对 dangling 指针做指针减法是 UB）。
- `runtime/AriaVM.hpp`/`.cpp`：解释器（M1-M4 已落地）。`run()` 返 `Result<Value, Error>`（成功=返回值，失败=未捕获运行时错误；M6 协程挂起将扩三态含 `Yielded`）。两个执行入口：`run(ObjFunction*)`（执行已编译函数）与 `run(SourceFile& source, ObjModule& module)`（**编译并执行**：经 `Compiler{gc_}` 把 `source` 编进 `module` 的入口 `ObjFunction`，编译失败原样透传首错 `Error`，成功即委托 `run(ObjFunction*)`；`Compiler` 每次就地构造，`source` 须存活到 `compile()` 返回（编译期 `Error` 构造时烘位置串需 `SourceFile` 存活）；`Error` 构造后自有位置串、不再持 `SourceLoc`/`SourceFile*`，故 `run()` 返回后 `source` 即可释放，`module` 由调用方提供身份、编译期由 `CodeGen::compile` 内部 `make_guard` 根化）。另有两个 **turnkey interpret 入口**返回 `InterpretResult` 枚举（`Ok`/`CompileError`/`RuntimeError`/`LoadError`，对齐 clox）：`interpret_from_src(StringView src)`（构造 `SourceFile` 名 `<script>` + 合成入口模块 `<script>`/cwd）、`interpret_from_path(StringView path)`（`SourceFile::from_path` 读盘，失败返 `LoadError`；按路径派生模块身份经 `fs::module_name_and_dir` 拆为 name=basename 去 `.aria`、dir=dirname(absolute(path))，`name` 为空（路径非合法文件模块）亦返 `LoadError`）。interpret 内部把错误渲染到 stderr 后只回类别--`Error` 已自有位置串、与 `SourceFile` 解耦，turnkey 入口内部构造/读盘的 `SourceFile` 即便返回后销毁也不影响已渲染的 `Error`，无悬垂问题，故无需 VM 源注册表；共用私有 `interpret_run(SourceFile&, ObjModule&)` 自己 `Compiler{gc_}.compile` 编译 + `run(ObjFunction*)` 执行、按**失败阶段**分类（编译期失败 -> CompileError「主入口编译失败，程序从未开始执行」；run 期失败 -> RuntimeError。2026-09 起不按错误码大类映射：运行期才抛的 `UndefinedVariable`（码已随迁 Runtime 类，消息前缀 `Runtime:`）与经 IMPORT 异常通道传播的**被导入模块编译期错误**（主模块已在执行、可被 try/catch 捕获，「可 catch 的错误」不构成 CompileError）均归 RuntimeError）。`run(ObjFunction*)`：**程序入口仪式** -- 入口断言 `current_ == &main_ctx_`（M6 前恒真；M6 单循环切换模型下升格为永久不变式 -- run() 是唯一驱动入口，resume/yield 不重入，见 vm-design.md §4.9）+ 源根入口槽 `[0]` 原地替换为入口模块 `dir_` + 前后 `reset()` 清场（重复调用先清场：HALT 收场的上一轮不弹帧，不清场会把新帧叠在陈旧帧上；结束清场避免 run() 外 GC 经 tracer 标到陈旧栈值）+ 委托私有 `run_function(fn)`。**`run_function(ObjFunction*)`**（执行本体，无入口装饰）：入口 fn 现场包空闭包（顶层也闭包，M4；fn 跨 new_closure 的 GC 点 make_guard 兜底，闭包建成立即入栈 -- push 无 GC 点、入栈即经值栈根，无跨 push 守卫；入帧后另有帧 tracer 双根）后压 callee + `enter_frame` 进帧 -> `dispatch_loop()` 主循环，作用于 `*current_`（与 dispatch_loop/raise 同源；入口断言保证等价于直访 main_ctx_）-- 未来**重入**的接缝：指令执行中临时运行一个 ObjFunction（原生回调调 aria 函数 / 嵌入宿主调函数，见 vm-design.md §4.7「回调 aria 函数属未来机制」）经此进入，故不播源根、不 reset（重入调用者的栈不可冲掉）、不断言主上下文；落地时升公开，尚欠 dispatch_loop 按基线帧深退出（现仅 `frames().empty()` 返回，中途重入会穿掉调用者帧）与实参布线。**GC 已启用**：值栈 `[base, top)` + 各活动帧 `closure`/`module` + open upvalue 开链经 VM 根 tracer 标根（见下），`IMPORT`/`DEF_GLOBAL` 等已按「栈即根」前置编写（peek-not-pop）。`IMPORT` 取到模块对象后 `current_->push(module)` 压栈（不再自绑 globals，绑定交 CodeGen 按 `DEF_GLOBAL`/值填槽走）；`module` 经 `modules_` 根可达，非移动 GC 故 push（栈溢出增长走 Buffer 重分配）期间指针稳定，**不加守卫**，入栈后另经值栈根可达。`JUMP_BACK`（循环回边）为 safe point 调 `gc_.maybe_collect()`。指令子集：常量/字面量（`LOAD_CONST`/`LOAD_IMM`/`LOAD_NIL`/`LOAD_TRUE`/`LOAD_FALSE`）、局部槽（`LOAD/STORE_LOCAL` + `_L` 长变体，peek-store）、**全局**（`DEF/LOAD/STORE_GLOBAL`：`DEF` upsert 创建/覆写当前模块 `globals`；`LOAD` 先查模块 `globals`，miss 回退 VM 级 `builtins_` 表（Python 式 globals -> builtins 查找链，内置 type/len/str/assert 经此解析），再 miss 报 `UndefinedVariable`；`STORE` 仅写模块 `globals`、未命中报 `UndefinedVariable`（**不**回退 builtins -- 赋值不隐式创建，必须先 var 声明，见 grammar.txt §205-206））、算术/比较（经 `run_binary_numeric<Op>`：双 Int 走整数路径、任一 F64 升浮点；int 除/模零报错、f64 按 IEEE）、相等（`EQUAL/NOT_EQUAL` 走 `value_equal`、`STRICT_EQUAL/STRICT_NOT_EQUAL` 走 `value_identical`）、`NOT/NEGATE`、栈操作（`POP`/`POP_N`/`DUP`/`DUP2`）、`JUMP*`（u16，方向在 opcode，偏移以读完操作数后 ip 为基准；含 `JUMP_TRUE_OR_POP`/`JUMP_FALSE_OR_POP` 短路）、`CALL`（`ObjClosure` 经 `call_closure` 进帧查 arity/帧溢出 + `ObjNativeFn` 同步调用，见 `vm-design.md` §4.7；M4 起 callable 收敛为闭包，`ObjFunction` 退为常量池内部物、不再以 callable 语义统一；现为 main_ctx_，M6 单循环切换模型（Wren 式，见 vm-design.md §4.9）：resume/yield 即原生函数、CALL 善后点采用新 current_、dispatch_loop 永不重入，切换点唯一且显式；`call_native` 事后簿记（drop/断言）一律落在 entered_ctx 上，M6 切换对其透明、无需分支探测、CALL case 零改动，见 vm-design.md §4.9「切换协议」），均返 `bool` 成败信号 -- 失败时错误载荷已 raise 进 `*current_` 挂起错误寄存器（统一经 `AriaVM::fail`）、调用方据 `bool` 调 `unwind()`（M3：命中 handler 截栈派发 / 全未命中物化 Error 出栈，见下「VM 异常通道」），`call_value` 分发到 `call_closure`（arity/帧溢出检查 + 进帧）与 `call_native`（同步调用，失败载荷留寄存器交调用方走 unwind，不在本函数取出））、`RETURN`（弹返回值 + `exit_frame`（M4 起内置 `close_upvalues(frame.slots)`：关本帧被捕获局部，值迁入各自 upvalue 自持 -- 闭包跨 RETURN 存活的机制，槽区存活时迁值）；顶层主帧返回即返回程序结果，模块体帧（按函数名 == `<module>` 判定）则弹弃返回值、改压模块对象）、**闭包与 upvalue（M4 落地）**：`CLOSURE fn:u16`（`[] -> [closure]`：取常量池 `ObjFunction` 现场包 `ObjClosure` 并**立即压栈**（「栈即根」，跨捕获循环免守卫），再遍历 `fn->upvalue_descs()` 逐个建/复用 -- `is_local=true` 槽址 `frame.slots + index` 经 `capture_upvalue` 单点复用/新建插链（链上节点经 tracer 保命），`false` 穿透复制 `frame.closure->upvalues()[index]`；`add_upvalue` 的 Array push 走 `CLOSE_UPVALUE`（`stack_top()`）/ unwind 命中（`slots + stack_depth`，先于截栈，try 体被捕获局部随丢弃区间迁移，handler 帧不退不经 exit_frame）/ `reset()`（全链）、`HALT/PRINT/NOP`、**`IMPORT`（已落地）**：经 `resolve_module` 解析 specifier 为绝对规范路径（模块表键）-> `new_string` intern -> `modules_` 查表（`IMPORT path:u16`，栈效应 `... -> [module]`；绑定交 CodeGen 按 `DEF_GLOBAL`（顶层）/ 值填槽 + `mark_initialized`（嵌套）走）。命中(体已跑完/循环导入半初始化)复用并压栈；未命中调 `load_module` 编译(入口名 `<module>`，`set_entry`) -> 返回模块(体待 run-once)。**错误契约同 call_value 族**：返 `ObjModule*`，失败 `nullptr ⟺` 载荷已 raise 入 `*current_` 寄存器，调用方 `unwind()` 派发/物化；读盘失败/name 空经 `fail` 报 `ModuleNotFound`(带 IMPORT 站点位置，与 resolve_module 失败形态统一)，编译期 Error 就地 `new_exception` 原样装配箱透传(含被导入文件位置，不重烘)。**模块体帧判定**：不在 `CallFrame` 上设标志位,RETURN 按函数名 == `<module>`（`kModuleEntryName`，aria.hpp）识别 IMPORT 加载层驱动的模块体 ## VM 异常通道（throw/catch，M3 已落地）

aria 语言的 `throw/catch` 与 VM 检测到的运行时错误统一走 VM 自管机制（不引入 `SETUP_EXCEPT`/`END_EXCEPT`，不依赖 C++ 异常）：错误站点 raise 载荷入挂起寄存器 -> `AriaVM::unwind()` 自最内帧向外以 `last_ip`（指令起始，非已推进的 `ip`）反推 offset 查 `CodeUnit::try_records`（`find_try_handler`，嵌套取最内层），命中即先关被丢弃区间的开指（`close_upvalues(slots + stack_depth)`，M4：try 体被捕获局部随丢弃区间迁移，槽区存活时迁值）再截值栈（`Movement::truncate_stack` 至 `frame.slots + stack_depth`）、`ip` 跳 `handle`、载荷 push 落 catch 参数槽（恒 == stack_depth，值填槽无 STORE_LOCAL）；未命中帧先记跟踪三元组、关本帧区间开指（`close_upvalues(frame.slots)`，M4）再逐帧 `exit_frame` 后继续，全未命中从未捕获出口物化 Error。设计全文见 `vm-design.md` §4.5-§4.8/§7，踩坑对策见 `exception-implementation-pitfalls.md`（坑 #1-#16 全部落地）。

- **构成件（全部就位）**：`OpCode::THROW`（dispatch_loop 弹值 `current_->raise(v)`，原值入寄存器不包 ObjException -- catch 绑原值保类型、未捕获物化兜底 `UncaughtException`）；`CodeUnit::try_records` + `find_try_handler`（`TryRecord{begin, end, handle, stack_depth}` 四字段，按 begin 非降序二分 + 前溯，begin 相等（内层 try 是外层体首条语句）由反向扫描天然取最内层）；CodeGen `visitTryStmtNode`（入口预插占位 + 结尾回填保证升序）与 `visitThrowStmtNode`（见 compile.md）；`Movement::truncate_stack`（帧内回退，与 `FrameStack::truncate` 组成 unwind 完整回退）；`AriaVM::raise/fail`（装箱点一步烘位置 + 消息）与 `unwind`（private，仅 dispatch_loop 驱动期；入口断言寄存器非空）；`ObjException`（携码 + 完整烘焙消息，re-throw 保码；`to_error` 经 `Error::from_baked` 原码原消息回传供测试/嵌入方，未捕获出口经 `uncaught_error_parts` 拆件）；VM 根 tracer 标 `pending_error_`（raise 到 unwind 间跨安全点不回收）。
- **直报形态已退役**：dispatch_loop 内不再有 `return runtime_err(ctx, code, fmt...)` 式 Result 直传，全部站点走寄存器 + unwind；`Error` 仅在 `unwind` 未捕获出口物化（+ 堆栈跟踪烘焙），与 CLAUDE.md 通道 2 的描述一致。
- **未捕获堆栈跟踪（坑 #16）**：`unwind` 帧遍历中对未命中的帧先记 `TraceEntry{fn, mod, ip_off}` 再 `exit_frame`，全未命中时反转为外 -> 内（Python 式 most recent call last）逐帧烘焙 `\n  at <fn名> (<loc>)` 进 `Error.message_` 尾部；行号源与位置前缀同装箱点（`last_ip` 查 `line_for_offset`，文件模块 abs_path / 合成模块 `<name>`）。透传的被导入模块编译期 Error 不经 unwind，无跟踪。
- **finally 已裁撤（2026-09，善后后继 defer 已降为可选后续、不再绑定 M4）**：`finally` 回归普通标识符；try 无 catch 报 `TryWithoutHandler`（消息「try 须有 catch」）。
