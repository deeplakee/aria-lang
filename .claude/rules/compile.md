# compile 层模块参考

Lexer / Parser 的实现应与 `docs/grammar.txt`（语言文法规范，留在 `docs/`）保持一致，改文法时同步更新相关代码与测试。

- `compile/TokenType.hpp`：`TokenType`（覆盖文法全部终结符，含 23 关键字）+ 可读名表 `kTokenNames` + 拼写表 `kTokenLexemes`（表项 `Pair<StringView, bool>`：固定拼写 + 是否关键字；关键字/运算符/标点/下划线为字面拼写，字面量与 EOF 记空串）+ `to_string(TokenType)`（constexpr 查表，非法值 ASSERT）+ `lookup_keyword`（顺序扫 `kTokenLexemes` 关键字行（`is_keyword` 置位），大小写敏感）。枚举/名字表/拼写表由 `ARIA_TOKEN_LIST(X)` 全量注册表（X-Macro 单一事实源，条目 `X(名字, 拼写, 是否关键字)` 三列）同源展开，新增类型加一行即收口、名字串经 # 派生；逐值注释用块注释（行注释会吞续行符）。X-Macro 风格统一对齐 `code.hpp` 的 `ARIA_OPCODE_LIST` 先例：注册表宏顶格，条目宏 `ARIA_<首词>_<ROLE>` 在展开点前 define、容器单行内联 use、随行 undef（影响面最小）。
- `compile/Token.hpp`：`Token`（type+lexeme(`StringView`)+loc+`TokenValue`，工厂 `make_integer`/`make_float`/`make_string`）。`TokenValue = variant<monostate,i64,f64,String>`。访问器 `type()`/`lexeme()`/`loc()`；谓词 `is_eof()`；取值 `int_value()`/`float_value()`/`string_value()`。
- `compile/Lexer.hpp`：`Lexer::tokenize(SourceFile&) -> Result<List<Token>, List<Error>>`。错误恢复式词法分析：词法错误记入 `List<Error>` 后推进继续扫，达 `kMaxErrors`(=32) 置 `is_fatal_` 停止；无错才返回 token 流（含末尾 Eof）。基于 `utf8::decode_one` 按码点推进，`src_` 以 `\0` 结尾作哨兵。静态入口 `Lexer::tokenize`，内部一次性构造，无空态/复用。
- `compile/ast.hpp`：AST 节点层次（`ASTNode` 根 -> `StmtNode`/`ExprNode`/`PatternNode` 分类基 -> 各具体节点；`ProgramNode : ASTNode` 为根的直接子节点，持顶层声明列表）。`ASTNode` **不可拷贝、不可移动**（节点总经 `UPtr` 堆分配，移动的只是指针），运算符枚举 `Op::Binary`/`Op::Unary`/`Op::Assignment`（收口于 `namespace Op`，与 `TokenType` 解耦；`Op::to_string(Binary/Unary/Assignment)` 返运算符字面），辅助值类型 `Param`/`MatchPattern`/`MatchArm`/`MatchExprArm`/`VarBinding`/`MapEntry` 等。节点持 `SourceLoc`，`loc_line()` 取行号（`static_cast<u32>(loc_.line())`，无 0->1 兜底），`dump(indent)`/`display()` 渲染树形文本（节点 dump 统一经 `detail::ast::dump_node(indent, header, kids...)` 变参收口，子项按 UPtr 空安全/值/List 三族泛型 `dump_child` 自动分派（值子项族由 `Dumpable` concept 约束），基础设施与 `write_line` 同在 ast.hpp；`TryStmtNode` 的 catch 子树 indent+2、`MatchPattern` wildcard 早返回、条件拼 header（DefDecl super= 等）保留手写）。每个具体节点有 `accept(AstVisitor&)` override（双分派：节点调 `visitor.visitXxxNode(*this)`，见 `compile/AstVisitor.hpp`）。
- `compile/Parser.hpp`：`Parser::parse(List<Token>) -> Result<UPtr<ProgramNode>, List<Error>>`。递归下降，各函数与文法非终结符一一对应；内部用 `AriaCompileException` 在递归下降深处传播语法错误，`declaration()` 层捕获 + panic-mode `synchronize()` 恢复式收集 `List<Error>`（同 Lexer）。游标辅助 `peek(ahead=0)`/`check(t)`/`match(t)`（= check+advance）/`advance()`/`previous()`/`expect(t, what)`（失配抛 `AriaCompileException`）/`expect_identifier()`/`synchronize()`；for/for-in、fun 声明/lambda、`{` block/mapExpr 等按调用上下文消歧。静态入口 `Parser::parse`，内部一次性构造，无空态/复用。
- `compile/AstVisitor.hpp`：AST 访问者（Visitor）模式接口，作为代码生成阶段「字节码编译器」（AST -> CodeUnit）与语义分析器等遍历类的抽象父类。每个具体 AST 节点对应一个 `visitXxxNode(XxxNode&)` 纯虚方法（子类须逐一 override，编译器据此强制覆盖全部节点类型，避免漏处理）；双分派由节点的 `accept(AstVisitor&)` 完成（见 `compile/ast.hpp`）。本头只前置声明各节点类型（只用节点类型引用，与 `ast.hpp` 解耦），子类需自行 include `ast.hpp` 访问节点成员。参数用非 const 引用（子类可在遍历中读写节点）。具体子类：`CodeGen`（见下）。
- `compile/FunctionCtx.hpp`/`.cpp`：单函数编译上下文，收口每函数可变状态。持 `enclosing_`（外层上下文裸指针；所有权：入口 fn 上下文由 `ModuleCtx` 构造期 `new`、析构沿 enclosing_ 链 `delete`；子上下文由 `compile_function` `new`--成功路径 `delete`、出错路径不 delete 交 `~ModuleCtx` 走链。父函数编译期长于子函数（栈帧包住），故 `enclosing_` 裸指针在子生命期内稳定；`enclosing_==nullptr` 即入口 `<main>`）、`fn_`（当前函数；其 CodeUnit 由 CodeGen 经 `cur_cu()` 派生（= `&fn_->unit()`，随 ModuleCtx 游标），**不缓存 `cu_` 于本类**）、`locals_`（clox 风格局部栈，`locals_[0]`=哑元 slot 0=callee（普通函数/静态方法/入口，空名词法不可达；实例方法族则为具名局部 this，见下 FnKind）；1..A=形参；A+1..=体局部）、`scope_depth_`、`loop_stack_`（循环上下文栈）、`upvalues_`（M4 闭包：本函数捕获描述表 `List<UpvalueDesc>`，体编译期间经 `add_upvalue` 登记，成功路径由 `compile_function` 尾部整表 flush 进 `fn->upvalue_descs()`）、`kind_`（M5 函数种类 `FnKind`：Function/Lambda/StaticMethod/Method/InitMethod；this 解析「沿 ctx 链找最近实例方法」与 super 判据「当前帧为实例方法族（is_method）」两判据消费，定义于 compile/FnKind.hpp（含 to_string 与 is_method；AST 侧 FunDeclNode::kind 同用此枚举），含 `kThisName = "this"`--this 是关键字不可能与用户标识符撞名，可安全参与 find_local/resolve_upvalue 嵌套捕获）。入口/嵌套共用单构造 `FunctionCtx(ObjFunction* fn, FunctionCtx* enclosing = nullptr, FnKind kind = FnKind::Function)`（enclosing 空 = 入口 `<main>`，否则嵌套指向外层；kind 随子上下文：实例方法族时槽 0 为具名局部 `this`（caller 压 receiver 占槽；arity 不含 this）。**只负责登记**：`add_local(name)` 压 `Local{name,scope_depth_,is_captured=false}` 返 slot（纯登记，不发射/不查重）；`add_upvalue(desc) -> Opt<u8>`（M4：同 `(is_local,index)` 去重复用，upvalue 索引域 u8、上限位置 `kMaxUpvalues`（=255，定义于 FunctionCtx.hpp，与 kMaxConstants/kMaxLocals 同族语义：值即操作数位宽上限、越界判定统一 `>`，容量 = 上限 + 1 即 256），追加将越出索引域（size > kMaxUpvalues）返 nullopt 交 CodeGen `fail TooManyUpvalues`；纯登记不发射）；`is_defined_in_scope(name)` 当前 scope 是否已定义同名（外层同名允许 shadow）；`find_local(name)` 返最近同名 slot；`begin_scope`/`end_scope`（退出块作用域：`--scope_depth_` 后弹出原 scope 的局部（depth > 新 scope_depth_，自最内层向外清，真正从编译期 `locals_` 移除，局部出作用域后续不可再引用；slot 0 哑元 depth=0 恒在弹区界外）；break/continue 不得走此--跳转后的语句仍在作用域内可引用这些局部，须保留登记；弹区清理指令（整区 `POP_N` + 含被捕获局部时一条批量 `CLOSE_UPVALUE`）由 CodeGen 先经 `emit_pop_locals_to` 发射（需在登记移除前做），本方法只管登记收尾）。`Local`/`LoopCtx` 为 `aria` 命名空间下简单聚合（见头文件）。`LoopCtx`：`back_target`（循环头/条件求值点——回边恒跳此，后向 continue 亦跳此）/`continue_fwd_patches`（`Opt<List<u32>>` 前向 continue 占位通道——nullopt = 本循环 continue 走后向跳 back_target，仅 for 带 incr 在入栈前 emplace 打开）/`loop_scope_depth`（循环体 scope 深度，break/continue 弹局部至此）/`exit_fwd_patches`（前向退出占位：循环头条件假跳 JUMP_FALSE + 各 break 的 JUMP，收尾 `emit_loop_backedge_and_exits` 统一回填 -> L_end）。构造由调用点指定名初始化 `LoopCtx{.loop_scope_depth=..., .back_target=...}`（其余成员走默认成员初始化：`continue_fwd_patches=nullopt`、`exit_fwd_patches` 空；仅 for 带 incr 在入栈前 emplace 打开），条件假跳占位在入栈前登记进 `exit_fwd_patches`。**循环上下文随函数走**：进新函数即得空 `loop_stack_`，故 break/continue 不会跨函数绑定到外层循环（函数边界天然隔离循环上下文）。`LoopCtx` 字段语义与三种循环（while/for/for-in）+ break/continue 的占位回填用法详见 `.claude/reference/compile/loopctx.md`。
- `compile/ModuleCtx.hpp`/`.cpp`：模块编译上下文，收口每模块状态--模块句柄 `module_`（`ObjModule*`）+ 当前函数上下文游标 `current_fn_ctx_`（`FunctionCtx*` 裸指针，公有，**兼拥有入口 fn 上下文**：构造期就 `m.entry()` `new`、析构 `delete`）+ 顶层全局名注册表 `defined_globals_`（`HashSet<String>`，按名字**内容**判等，不依赖 intern 指针，私有）。**单成员兼两职**：`current_fn_ctx_` 既是入口 fn 上下文的所有者（ctor 分配 / dtor 释放），又是「当前编译到哪个函数」的游标--初始 = 入口（`enclosing_==nullptr`=entry）。子函数上下文由 `compile_function` `new` 分配、enclosing_ 回父、游标摆向子（`mod_ctx_->current_fn_ctx_ = child`）；**成功**路径 compile_function 还原游标（`= child->enclosing_`）并手动 `delete child`，**出错**路径 `fail()` 抛 `AriaCompileException` unwind（不还原游标、不 delete 子，见 CodeGen）。无需另设 owner + cursor 两个指针。「当前 CodeUnit」不再单独存，由 CodeGen 经 `cur_cu() = &cur_fn_ctx()->fn_->unit()` 派生，随游标自动切换（免两指针同步 save/restore）。entry 判定 = `current_fn_ctx_->enclosing_ == nullptr`。**析构走链**：`~ModuleCtx` 沿 enclosing_ 链从 `current_fn_ctx_` 走到 entry 逐个 `delete`（先存 next 再 delete），无论游标在哪儿都对--成功时游标 = entry 仅删 entry，出错时游标停在 deepest 未释放子，走链释放整条活动链 + entry。无需「游标必回入口」不变式与 ASSERT：异常 unwind 保证出错后无 cur_cu()/cur_fn_ctx() 访问（见 CodeGen），析构走链即清理。**轻封装**：`module_` / `current_fn_ctx_` 公有（CodeGen 直接读写--后者在 `compile_function` 进出函数时摆动），`defined_globals_` 私有（仅经内联方法 `declare_global` 访问）；一个内联方法 `declare_global(StringView name)`（`return defined_globals_.insert(String{name}).second`，true=新登记 / false=已存在，调用方 `fail RedefinedVariable`）；另一定义于 .cpp 的 `is_global_scope() const noexcept`（`current_fn_ctx_->enclosing_ == nullptr && current_fn_ctx_->scope_depth_ == 0`，收口「当前是否模块顶层作用域 -> 定义为全局」判定，供 `visitVarDeclNode`/`compile_function` 复用，需 `FunctionCtx` 完整类型故非内联）。构造函数 `ModuleCtx(ObjModule* m)`（.cpp 定义）：**要求调用方先 `module.set_entry(entry)`**，构造期 `ASSERT(m->entry() != nullptr)`，`module_{m}` 后 `current_fn_ctx_ = new FunctionCtx(m->entry())`（自建入口 fn 上下文 = 游标就位）。与 `FunctionCtx`（每函数）对齐：模块 > 函数 > 作用域 三层各一席。**一次性**：不复用、无 `reset`，每个模块编译用全新实例（`CodeGen::init_module` 入口 `std::make_unique<ModuleCtx>(module)`）。**特殊成员**：`current_fn_ctx_` 是 `new` 分配的裸指针，析构沿 enclosing_ 链 `delete`（需 `FunctionCtx` 完整类型，故 `~ModuleCtx()` 声明于头、定义于 .cpp）；copy / move 删除（ModuleCtx 一次性、不可移动）--由调用方以 `UPtr<ModuleCtx>` 持有（CodeGen 持 `UPtr<ModuleCtx> mod_ctx_`，compile 入口 `make_unique`、遍历后 `reset()`、`~CodeGen` 自动释放），无需 move。`gc_`（共享引用）**留 `CodeGen`** 不入此。首错经 `AriaCompileException` 抛出即 unwind（CodeGen 无 `error_` 成员），天然「整个 pass 的第一个错停住」（将来一次 pass 编译多模块时，模块 1 的异常即中断整 pass）。
- `compile/CodeGen.hpp`/`.cpp`：字节码代码生成器 `CodeGen final : AstVisitor`，单遍合一（clox 风格）--一次 AST 遍历同时做名字解析 + 语义检查 + 字节码发射，把 `ProgramNode` 编译为模块入口 `ObjFunction*`（arity 0、名由 `compile` 的 `entry_name` 参数定：主入口模块传 `<main>`、运行期导入模块传 `<module>`，模块体包装）。状态分离：每函数可变状态交 `FunctionCtx`，每模块状态（模块句柄 + 当前函数上下文游标 `current_fn_ctx_`（兼拥有入口 fn 上下文：ctor `new`、dtor `delete`）+ 顶层全局名注册表）交 `ModuleCtx`（见 `compile/ModuleCtx.hpp`），形成「模块 > 函数 > 作用域」三层。`CodeGen` 持 `UPtr<ModuleCtx> mod_ctx_`（ModuleCtx 一次性、不可移动；generate_bytecode 入口 `make_unique<ModuleCtx>(module)`，随一次性对象析构沿 enclosing_ 链释放）；「当前函数」不再作 CodeGen 成员--游标 `current_fn_ctx_` 寄存于 `ModuleCtx`（公有），CodeGen 经内联 `cur_fn_ctx()`（= `mod_ctx_->current_fn_ctx_`）只读访问、`compile_function` 经 `mod_ctx_->current_fn_ctx_ = ...` 摆动；「当前 CodeUnit」不再单独存，由 `cur_cu()`（= `&cur_fn_ctx()->fn_->unit()`，.cpp 定义需 ObjFunction 完整类型）派生，随游标自动切换（免两指针同步 save/restore）。`module_` / `current_fn_ctx_` 公有、`defined_globals_` 私有，CodeGen 直接经 `mod_ctx_->` 读写（前者）/经 `declare_global` 访问（后者）。**emit 解耦**：字节码编码逻辑（`emit_op`/`emit_byte`/`emit_word`/`emit_pop_n`/`emit_jump`/`patch_jump`/`emit_jump_back`/`emit_load_local`/`emit_store_local`/`size`）**下沉 CodeUnit**（见 `bytecode/CodeUnit.hpp`），CodeGen 不再自持这些薄包装；发射目标由 `cur_cu()`（派生自 ModuleCtx 游标 = 当前函数 `fn_->unit()`）决定。游标在 `compile_function` 进/出函数时摆动，`cur_cu()` 随之自动切到子/父 unit，无需 save/restore。越界（跳转偏移/回边超 64KB）由 CodeUnit 方法返 bool，CodeGen 经失败翻译层 `patch_jump_or_fail(src_off,loc)`/`emit_jump_back_or_fail(target_off,line,loc)` 翻译为 Error。**单层 _or_fail（操作 + 失败即 fail）**：`add_constant_or_fail(Value,loc)->u16`（溢出 `>kMaxConstants` -> `fail CodeUnitTooLarge`，否则 `cur_cu()->add_constant` 返索引；CodeUnit 内部 ASSERT 兜底永不被触达）、`add_name_or_fail(s,loc)->u16`（`new_string` intern 后经 `add_constant_or_fail` 入池，复用溢出检查，无守卫--trivial push 不触发 GC）、`define_local_or_fail(name,loc)->u16`（同 scope 重名 -> `fail RedefinedVariable`、`>kMaxLocals` -> `fail TooManyLocals`，否则 `add_local` 纯登记标未初始化、不发指令）、`add_upvalue_or_fail(ctx,desc,loc)->u8`（ctx 显式传入：resolve_upvalue 沿 enclosing_ 链递归登记、非恒 cur_fn_ctx；追加将越出 u8 upvalue 索引域 -> `fail TooManyUpvalues`，否则返回 upvalue 索引）、`resolve_name_or_fail(name,loc)->ResolvedVar`（局部 -> Local / 外层 -> Upvalue / 否则 Global 分支经 `add_name_or_fail` 入池，溢出即 `fail` 持 loc）供 visit 层（有节点 loc）调用：失败即 `fail(...)`（`[[noreturn]]`，之后值恒有效）并**返回解包值**；`patch_jump_or_fail(src_off,loc)->void`/`emit_jump_back_or_fail(target_off,line,loc)->void`/`declare_global_or_fail(name,loc)->void` 同一职责约定但底层返 bool、无解包值，故 void 封装仅翻译失败。声明绑定收口 `bind_stack_value(name,loc)`（值已在栈顶的声明名：全局 -> declare 判重 + `DEF_GLOBAL` 弹值定义 / 局部 -> 值填槽 declare；行号取 loc 声明行现场求值；var/fun/def/import 四处共用，var 的初始化器先于绑定求值）。每个 `_or_fail` 直接收口「操作 + 失败翻译」、无中间薄封装层（`add_name_or_fail` 经 `add_constant_or_fail` 复用溢出检查免拷逻辑；`define_local_or_fail` 的失败分支为两行直白 `if...fail`）。与 CodeUnit 跳转 bool 同一层次约定。**值填槽**：`define_local_or_fail` 仅 `add_local` 登记（不发 `LOAD_NIL`，非 clox 预占槽），登记即初始化、无独立 init 状态。**关键不变式**：声明名登记时值已压栈，「下个局部 slot = 当前栈高」，初始化器/`LOAD_NIL`/`LOAD_CONST` 值恰好压在 slot 成为该局部，无需 store/pop。var 的初始化器先于声明名求值（init 不登记当前帧局部，init 里的同名引用沿 resolve 链落外层：遮蔽场合捕获外层、落全局运行期 `UndefinedVariable`），var/fun/def/import 四声明流绑定统一 `bind_stack_value`。for-in `<iter>`/pattern 亦用值填槽（见下 for-in lowering），值填槽不变式对所有局部成立，无例外。形参 caller 压栈后登记。**上下文所有权**：见 `compile/ModuleCtx.hpp` 条--入口 fn 上下文由 `current_fn_ctx_` 自拥有，`compile_function` 成功路径删子并还原游标、出错路径交 `~ModuleCtx` 走链释放。**错误通道**：与 Parser 同--编译期深层 `fail()` 抛 `AriaCompileException`（持 `Error`，`[[noreturn]]`），自动 unwind 跨 visit 递归栈，`compile()` 顶层 `catch (AriaCompileException& e)` 翻译为 `Result`（`return std::unexpected(e.error())`，`mod_ctx_` 随一次性对象析构释放）。无需 `error_` 成员 / `ok()` / 各 visit 的 `if(!ok()) return` 守卫--throw 即 unwind，首个错误自然即止。`compile(GC& gc, ProgramNode&, ObjModule*, StringView entry_name)`（静态入口，`entry_name` 无默认值）-> `Result<ObjFunction*, Error>`：入口 `gc_.make_guard(module)` 把 module 入临时根贯穿全程（**GC 已启用**，同 `run()`）：经 `module.entry_ -> 常量池 -> 嵌套 fn 常量池 -> ...` 整链根化建设中 ObjFunction/常量池 ObjString；每个子 fn 在 `compile_function` 起始即 `add_constant_or_fail` 入父常量池（先于编译体），入池即经 module - `compile/Compiler.hpp`/`.cpp`：编译编排器 `Compiler`，收口「源文件 -> 可执行 `ObjFunction`」端到端链路。本身不做词法/语法/代码生成/磁盘 I/O--按序串联 `Lexer` -> `Parser` -> `CodeGen`，把三阶段 `Result<..., List<Error>>`（词法/语法，取 `errors_[0]`）/`Result<..., Error>`（CodeGen 已是单 Error）统一翻译为单个 `Result<ObjFunction*, Error>`（首错即止）。**吃实际的 `SourceFile`，不捏造源**：`compile()` 入参为 `SourceFile&`（调用方加载/构造的真实源文件--磁盘文件经 `SourceFile::from_path` 读盘、REPL/嵌入由调用方按需构造），本类只读其 `content()` 做词法，不拥有、不重建源文件；无 `source_` 成员、无 `source_name` 参数--源的身份（name/path）就是 `SourceFile` 自带，错误渲染 `path:line:col` 取自实际源文件。**`SourceFile` 生命期契约**：AST 节点持 `SourceLoc`（内含 `SourceFile*`），但 AST 仅 `compile()` 内部消费、不外返；编译失败返回的 `Error` 在构造期已把 `SourceLoc` 烘进自有 `message_` 串、不再持 `SourceFile*`。故 `source` 只须存活到 `compile()` 返回（烘位置串在此时完成），返回的 `Error`/`ObjFunction` 均不依赖 `source`，调用方可立即释放/move `source`（`SourceFile` 含 `String`，SSO 短串 move 会改 content 地址，但 `Error` 已不指向它，无影响）。**静态服务**：`Lexer::tokenize`/`Parser::parse`/`CodeGen::compile(GC&, ...)`/`Compiler::compile(GC&, ...)` 均为静态入口（前三者内部一次性构造），无跨 `compile()` 复用。**GC 同源**：`compile` 的 `gc` 参数（与 VM 同一 GC），编译期分配的 `ObjFunction`/`ObjString` 归此 GC、与后续 `run()` 同源；编译期 GC 已启用--`CodeGen::compile` 入口 `make_guard(module)` 自守 module，故调用方无需为编译期再守模块（module 须是 GC 管理的合法 `ObjModule`）。接口 `compile(GC& gc, SourceFile& source, ObjModule* module, StringView entry_name)`（静态入口，`entry_name` 无默认值）-> `Result<ObjFunction*, Error>`：成功返入口 `ObjFunction*`（arity 0、名 `entry_name`，归属 gc、须在 gc 存活期使用）；失败返首错 `Error`。`entry_name` 透传给 `CodeGen`：主入口模块传 `kMainEntryName`（`<main>`）、运行期导入模块传 `kModuleEntryName`（`<module>`），调用方显式传入、无默认。与 `CodeGen` 分工：`CodeGen` 是「AST -> CodeUnit（包在 `ObjFunction`）」代码生成器；`Compiler` 是「`SourceFile` -> AST」(`Lexer`/`Parser`)+「调 `CodeGen` 产出 `ObjFunction`」编排层，不做磁盘 I/O（加载源文件是解释器入口/REPL 职责）。无状态、静态入口。测试 `tests/test_compiler.cpp`：经 `Compiler` 编排层端到端 `compile -> AriaVM::run`（非手拼），`SourceFile` 经 `unique_ptr` 持堆稳定地址活到检视完返回值/错误；含算术/递归/全局+while/var 自引用运行期 `UndefinedVariable`（函数内无外层时 init 落全局双 miss）/语法错误，stress GC 锻炼编译期+运行期根接线。
