# 词法层测量纪律与被否方案

> 源码位置：`src/compile/Lexer.hpp` / `Lexer.cpp`（主循环、消费辅助）、`src/util/source_file.hpp`（位置派生）
> 模块参考：`.agents/reference/compile.md`（Lexer 条）、`.agents/reference/util.md`（source_file 条）
> 用途：动词法性能之前先读这篇。这里只收**测量纪律**、**设计判断**与**已实测否决的优化**；机制描述在
> 模块参考里，不重复。测量数字是 bench 的输出，跑一次就有，不在文档里留档。

## 1. 怎么量（测量纪律）

- 配方：`clang++ -std=c++23 -O2 -DNDEBUG`、无 LTO、进程内 best-of-N 取最小；复现命令见 bench 文件头。
  **Release 默认开 LTO**，跨 TU 内联对词法读数影响显著，故统一以无 LTO 为基线。
- **不要用单发进程计时**：受前后进程与机器状态影响，会量出数量级失真的假读数；同轮对照、交叉重跑取
  稳定读数。
- 跨构建与机器状态有百分之几量级的抖动，差异小于此的量不要当结论。
- 基线取法：`git archive <commit> | tar -x -C /tmp/<dir>` 导出历史树编译对照--手工回退文件当基线既容易漏改、
  又会写坏工作区。**重配旧 build 目录不覆盖缓存里的 -D
  值**：跨配置对照前先看 `CMakeFiles/<target>.dir/flags.make` 实证旗标，缓存钉住的旧值会让「新配置」臂
  实为旧产物（特征：两臂读数逐毫秒一致）。
- 合成源分四形态压不同成本：`normal`（多行、注释/串/数字混杂，贴近真实源码）、`numeric`（数字字面量密集）、
  `cjk`（多字节密集）、`string`（字符串密集）；另有 `string_huge` 单行超长串一行。
- **计时外壳本身会引入数个百分点量级的噪声**：故 `lexer_bench` 每节的计时循环写死在原地、不抽公共外壳
  （`vm_bench` 相反，best-of-N 循环收在普通函数里）；跨二进制比绝对值也要先确认代码布局没变。
- **等价性验收**：位置/分派类改动只跑 ctest 不足以证明「零行为变化」。仓库里没有 token dump 工具，改这类
  路径时临时写一个（类型 | lexeme | 行列）对拍，外加词法错误场景的输出 diff，比断言更可靠。
- 基准程序：`bench/lexer_bench.cpp`（词法吞吐四形态 + 端到端编译 + 位置派生 + utf8 解码，须用 -O2 构建）。

## 2. 设计判断

词法优化的现状（机制见 `.agents/reference/compile.md` 的 Lexer/Token 条）：位置按需派生、消费辅助收口、
utf8 热/冷拆分、字符串普通段整段追加、关键字注册表拆分（纯表 + 长度早退）、token 表按源预留、Token
平凡化（无 tag union + 字符串解析内容后置）。均经 dump 对拍与双配置全量 ctest 验收等价。

- **位置不要在词法期烘进每个 token。** token 携带行列 => 每个 token 都要解析一次位置 => 逐 token 数码点，
  单行长文件退化成 O(n²)。位置只存偏移、行列在消费点派生之后，
  这个成因本身消失；列在生产代码里本来也只有错误渲染与测试读。
- **行解析必须带单条缓存。** 不带缓存每次二分，遍历密集的消费者上是纯开销；带缓存命中即常数级，成本被
  其他工作完全遮盖。
- **token 表按源预留 `reserve(src/2+1)`**：token 数 <= 字节数+1（EOF），故至多一次倍增、任何形态不劣于
  裸倍增；不带 `+1` 的形态在纯密集源有越界回退（已实测），`+1` 是刀口修复不是笔缀。
- **utf8 解码成本在函数体大小而非调用次数**：绝大多数调用是单字节 ASCII，执行路径极短，真正的开销是
  `decode_one` 在每个调用点被内联展开（多字节那套长度表/续接校验/组装/双重校验在各站点占据代码空间）。
  故热/冷拆分取 `detail::decode_multibyte` + `ARIA_NOINLINE`。

## 3. 已实测否决（勿重提，除非测量条件变了）

| 被否项 | 否决理由 |
| --- | --- |
| ASCII 优先分派（主循环抄成「按字节」与「按码点」两条类别链） | 收益依赖「代码恰好内联在循环体里」这一偶然性，抽成方法后即消失；撑不起两条重复类别链的维护成本 |
| 单链分派 + 条件取码点（`byte < 0x80 ? cp : decode_one(...)`） | 比完全回退还慢：合并成一条链后编译器无法为「纯 ASCII」与「含多字节」两条路径分别优化 |
| `skip_trivia` 的字节级分派 | 负收益，且多代码；空白是逐字节路径，逐次解码反而更快 |
| 标识符续接的 ASCII 字节循环 | 多一次四路布尔判定换掉 `decode_one` 的一次比较，实测更慢 |
| 指数段预视（先探再消费，替代消费后退回） | 位置只存偏移之后，回退就是 `pos_ = exp_pos` 一行、语义自明；预视要复制一遍指数扫描逻辑，净增代码且无正确性收益 |
| 在 `consume_codepoints` 内为 ASCII 另开快路径 | 该模板在多个调用点展开，多一条路径的代码体积比省下的那点解码更贵；ASCII 时 `decode_one` 本就返回「该字节、长度 1」，快路径只是把同一件事重写一遍 |
| 位置类型携带区间（`SourceSpan{start, end}`） | 调用点只读起点、`end` 从未被消费；类型已删 |
| 数字字面量收尾抽公共 helper | 三段尾部确实同构，但就地只有几行、错误文案就地完整；抽出后要把函数体挪进头文件才有望内联，实测数字密集源更慢，代价不值 |
| `\u{...}` 收集改只收 hex（连带把 from_chars 失败分支换成「缺少十六进制」） | 分支数不变、只换错误文案；且 `\u{1_2}` 的提示会从「含非合法 hex 字符」变成「缺少 '}'」，比现状更差 |

两个**不是**「被否」而是「按输入形态二选一」的取舍（取舍时看目标形态）：

- `scan_operator_or_punct` 的形参：无参版（函数内自读首字节）在常规源占优，有参版在单行密集源占优。
  取常规源，故保持无参。
- 行表缓存命中率对 AST 遍历序敏感：顺序访问走缓存，随机序退到每次二分。新增非按源序访问行号的消费者时
  要重新评估缓存形态。

## 4. 基准覆盖与缺口

- **已覆盖**：四形态词法吞吐（`normal` / `numeric` / `cjk` / `string`）、端到端编译、位置派生原语、utf8
  解码微基准。
- **仍缺**：词法时间的分布未逐项拆解，仅位置记账与逐 token 分派两块量过并已修；`decode_one` 自身、
  `Token` 构造各自占多少没有单独测过。

## 5. utf8 解码的判断

- 目标应放在**多字节路径**（长度表、续接校验、组装、双重校验的指令数与分支），它是 CJK 源解码成本的
  主体；ASCII 路径已是最优形态，任何「统一成状态机」的做法都可能把 ASCII 拖慢 -- 本层已多次实测到这类
  反效果（§3）。
- 收益上限有限：解码只占整源词法的一部分，状态机仍要逐字节查表与累积，实际收益会明显小于「解码全部
  消失」的上限。
- 动手前先跑 `bench/lexer_bench.cpp` 的 cjk 行与 utf8 节，量准基线再改。
