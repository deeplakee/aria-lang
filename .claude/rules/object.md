`Object.cpp`（默认语义一律「本类型不支持」，fail 后返失败信号；出声明因 vm.fail 是 AriaVM.hpp 内模板、两头互不 include）。① `load_field(AriaVM&, ObjString*) -> Opt<Value>` / `store_field(AriaVM&, ObjString*, Value) -> bool` - `object/ObjString.hpp`/`.cpp`：SSO 字符串（`kShortCapacity=15`，短串内联 / 长串 `long_chars_` 独立 buffer；`is_long()` 由 `length_ > kShortCapacity` 派生不存标志位），FNV-1a 哈希（经 `util::hash_str`）。访问器 `view()`/`length()`；`equals(const Object*)` override（先比指针 intern 命中快速路径、再比 `view()` 字符内容）；`to_string()` override 返字符内容原文（无引号，如 `hello`；显示与调试分叉的唯一子类型，两者都 override）+ `debug_repr()` override 返字面量形式 `"<转义内容>"`（util::escape_string 转义 + 双引号包裹，原 value 层 format_string 的职责下沉至此，反汇编常量池等调试上下文的字符串约定形态）。`new_string` 工厂（Phase 2 起经 GC `InternPool` 驻留：等价内容共享同一 `ObjString*`，命中不分配不 GC，未命中 `new_object` + `intern_insert`）。`new_string` 内部对 `intern_insert` 窗口**不加守卫**：`s` 虽此刻白色无根，但 `intern_insert -> InternPool::insert -> allocate<ObjString*>` 走 trivial 分配（永不触发 GC，见 `GC.hpp` 核心不变式），故 `s` 跨 insert 不会被回收。`name`/`module` 跨 `new_object` 顶部 `maybe_collect` 的守卫仍保留（那是真 GC 触发点，承重）。**协议 override（批 6）**：`load_index` 整数键 = 字节域（计划 D5，与 len 同域）产出单字节 1-char string（char 单字节重载 `new_string` intern 分配，receiver 经调用方值栈为根；多字节序列中间字节取该字节自身）、负数从尾计数、归一化后越界 IndexOutOfBounds、非整数 TypeMismatch；`store_index` 恒 TypeMismatch "string does not support subscript assignment"（不可变，键值不检查）；`load_field` 两步委托 VM 的 String bootstrap 类（`vm.string_class()`，runtime/builtins/StringBuiltins 的 11 方法表 upper/lower/trim/split/find/replace/substring/starts_with/ends_with/codepoint_at/iter），与 ObjList/ObjMap 同形；store_field 不 override（基类默认即正确行为）。
- `object/ObjFunction.hpp`/`.cpp`：函数对象（`ObjFunction final : Object`，`ObjType::FUNCTION`）：持 `CodeUnit unit_` 值成员（编译器经 `unit()` 直接操作裸字段 emit）+ `ObjModule* module_`（所属模块，词法归属，构造时传入、不可变、非空；VM 据此定位「当前模块 globals」）+ `ObjString* name_`（intern 同指针；**恒非空**，ctor ASSERT 非空--入口函数名 `<main>`（主入口）/`<module>`（导入）、lambda 名 `<anonymous>`、具名函数为声明名；`<>` 是正常标识符中不可用的符号，具独特辨识度；统一「每个函数都有名字」模型）+ `u8 arity_`（**固定参数数**，上限 255；不含 rest——varargs 函数帧参数槽深 = arity + is_varargs）+ `min_arity_`（必传参数数，<= arity，差额为带默认值参数；call_closure 区间检查下界，不足段印章垫充；rest 永非必传，不计）+ `bool is_varargs_`（末位参数为 ...rest：call_closure 只保元数下界、超出 arity 的实参打包成新 list 压入 rest 槽）+ `Array<UpvalueDesc> upvalue_descs_` 捕获描述表（`UpvalueDesc{bool is_local; u16 index}` 定义于头，纯标量聚合：is_local=true 捕直接外围帧局部槽 index、false 穿透复用外围闭包的第 index 个 upvalue；编译期 CodeGen 一次性 flush、运行期只读，`upvalue_descs()` 非 const + const 读口；存元数据、不进字节码流，CLOSURE 保持定长 3B；与 ObjClosure::upvalues_ 按下标一一对应；trace 不标）。访问器 `unit()`（非 const + const 重载）/`name()`/`arity()`/`module()`/`upvalue_descs()`（非 const + const 重载）。地址哈希型；`equals` 保持默认地址相等（函数无内容相等语义）；`trace()` 标 name_ + module_ + 委托 `unit_.trace`（常量池；module_ 回指形成 module<->entry 环，mark-sweep 三色标记天然破环）；`debug_repr()` 统一渲染 `<fn name>`（入口 `<fn <main>>`/`<fn <module>>`、lambda `<fn <anonymous>>`、具名 `<fn add>`；基类 to_string 默认委托之，显示同文案）；工厂 `new_function(gc, module, name, arity, min_arity, is_varargs)` **不替调用方守卫入参**（「每方只守自己创建的」），只做一次 `new_object`、无内部新建对象；调用方须在调用前自行根化 module 与 name（皆不保命：module 可能尚未入 VM 模块表、name 经 intern 是 weak root），跨 `new_object` 顶 maybe_collect；`StringView name` 便捷重载内部 intern name 并自守（工厂守「自己创建的」），调用方只需根化 module。
- `object/ObjUpvalue.hpp`/`.cpp`：upvalue 对象（`ObjUpvalue final : Object`，`ObjType::UPVALUE`，非拷贝/非移动）：闭包「捕获即引用」的载体（M4）。持 `Value* location_`（open 态指入值栈槽，grow_stack_ 搬迁后经 `set_location` 重绑；closed 态恒指 `&closed_`）+ `Value closed_`（ctor 播 `nil_val`，`close()` 时迁入自持值）+ `ObjUpvalue* next_open_`（侵入式开链节点，VM 按槽址降序维护链头；**不叫 `next_`**--与基类 `Object::next_`（GC 对象链字段）撞名，`GC::new_object` 经基类字段链接会被派生字段遮蔽）。访问器 `is_open()`/`value_slot()`（open -> `location_`、closed -> `&closed_`，LOAD/STORE_UPVALUE 统一走它，非 const + const 两重载）/`next_open()`/`set_next_open()`；`close()`（`closed_ = *location_; location_ = &closed_`）；`set_location()`（重绑用，仅 open 态，debug 断言）。`trace` 标 `*value_slot()`（open 标栈槽内值 / closed 标 closed_，两态同一地址语义）；upvalue 本体从不出现在 aria 值面（语言层不可见），`debug_repr` override 渲染 `<upvalue>` 稳定短文案（地址型描述噪声大且地址不稳；基类 to_string 默认委托之，随之同文案）。工厂 `new_upvalue(gc, Value* slot)`：入参是裸栈槽地址无对象可守，只做一次 `new_object`、无内部新建；返回白色无根，调用方须立即链入 VM 开链（链上节点经 VM 根 tracer 保命）。
- `object/ObjClosure.hpp`/`.cpp`：闭包对象（`ObjClosure final : Object`，`ObjType::CLOSURE`）：函数 + 捕获数组 + defining class。持 `ObjFunction* function_`（被包函数，恒非空，ctor ASSERT；callable 收敛为闭包后，运行期一律以 `ObjClosure` 进帧，`ObjFunction` 退为常量池内部物）+ `Array<ObjUpvalue*> upvalues_`（ctor 空态，VM 执行 CLOSURE 时按 `fn->upvalue_descs()` 捕获描述表逐个后填，之后只读；与描述表按下标一一对应）+ `ObjClass* defining_class_`（M5：方法闭包所属 defining class，ctor nullptr，VM 执行 MAKE_METHOD 注册时 `set_defining_class` 一次、之后只读；非方法闭包（静态方法 fun/lambda/其余）恒 nullptr。**一职双任**：super 来源（`LOAD_SUPER_FIELD` 从 `frame.closure->defining_class()` 直读）+ 方法性标记（读路径 `ObjInstance::load_field`/LOAD_SUPER_FIELD 据非空判绑 this，`is_method()` 访问器；判别按戳不按值类型）。挂闭包而非共享的 ObjFunction 常量：函数体内 def 执行 N 次产生 N 个类共用同一 fn 常量，superclass 运行期可重绑，戳共享 fn 会跨实例串错 super 链）。访问器 `function()`/`name()`（闭包的名 = 被包函数名，ObjString* 恒非空，与各 name-bearing Obj* 的 name() 同约定；.cpp 定义，需 ObjFunction 完整类型）/`upvalues()`（const Array&）/`upvalue_count()`/`defining_class()`/`set_defining_class`/`is_method()`；`add_upvalue(ObjUpvalue*)` 供 CLOSURE 执行期逐个后填（Array push 走 trivial 分配不触 GC，靠 GC 核心不变式免逐个守卫）。地址哈希型；`equals` 默认地址相等（同一 fn 的两次捕获是不同闭包，按身份判等）；`trace` 标 function_ + 全部 upvalue（upvalue 再各自标其槽值/闭值）+ defining_class_（容 nullptr；方法闭包经此级联标所属类）；`debug_repr()` 直取 function_ 名渲染 `<fn name>`（与纯函数同文案，trace_execution 兼容；不经 function_->to_string() 虚委托，调试路径保持一跳纯 C++ 访问器；闭包身份经 `type()`/`type_name()` 反射可见，基类 to_string 默认委托本方法）。工厂 `new_closure(gc, ObjFunction*)` 不替调用方守卫入参（「每方只守自己创建的」），只做一次 `new_object`、无内部新建；function_ 通常已入常量池（根），返回对象白色无根须立即发布进根。

- `object/ObjRange.hpp`/`.cpp`：range 对象（`ObjRange final : Object`，`ObjType::RANGE`）：`a..b`（含上界）/ `a...b`（不含上界）/ `a..`（无上界开区间）的运行期载体，壳定长纯值（无外挂 buffer、无子对象）：`from_` + `Opt<i64> to_`（nullopt = 无上界；含否上界无意义，ctor 归一 `is_exclusive_ = false`，`5..` 与 `5...` 是同一个值）+ `is_exclusive_`。内容哈希型不可变对象（哈希构造期烘焙；equals 按内容三字段全等；`===` 恒指针）。from > to 即倒序区间（迭代产出 from→to 递减，方向由迭代器推断、本体字段原样存，`10..1 != 1..10`）；空区间只剩 from==to 且不含上界。下标与 op_* 不 override（v1 无此需求）；`load_field` override 内置侧两步（委托 VM 的 Range bootstrap 类协议沿链查表，命中自持 `new_bound_method` 恒绑定 this，方法面注册入口 `register_range_builtins` 住 runtime/builtins/RangeBuiltins，v1 仅 iter），store_field 不 override；`debug_repr()` 渲染 `0..10`/`0...10`/`0..`（与源码拼写一致，显示同文案）。`resolve_slice_bounds(range, size)`（ObjRange.cpp 收口的切片端点解析：两端点各经 `util::resolve_index` 从尾计数（无上界取末元素），返归一化端点对 `Opt<Pair<usize,usize>>`；含否上界不折算进返回值、方向由端点大小关系自带；端点越界与空容器为 nullopt，报错由调用方就地烘焙）。工厂 `new_range(gc, from, to, is_exclusive)` / `new_range(gc, from)`（无上界重载，MAKE_RANGE unbounded 位）：端点是小整数非对象，无守卫义务；返回白色无根建成即发布。
- `object/ObjBoundMethod.hpp`/`.cpp`：绑定方法对象（`ObjBoundMethod final : Object`，`ObjType::BOUND_METHOD`，M5）：被绑定的方法值 + 绑定的接收者。`obj.m` 命中类表可调用值时由 LOAD_FIELD 现场绑定（new_bound_method），call_value BOUND_METHOD 分支按内部分派（闭包整形进帧 / 原生覆写槽 0 走 call_native 簿记）。持 `Value method_`（被绑定方法值，**闭包或原生函数**--ctor ASSERT 可调用（判定收口 `is_callable_value`，ObjBridge.hpp）；类表读路径仅对 defining class 戳定的方法闭包产生本类型（绑定原生由对象层直接构造承载，未来内建类型方法 uniform OOP 在各自协议内实现）；静态访问经 `Foo.m` 取出的是裸值不经本类型）+ `Value receiver_`（绑定的接收者，**Value 而非 ObjInstance\***--为将来内建类型方法（如 list.m）留泛化，当前只产 ObjInstance 接收者；闭包解包作方法帧槽 0 的 this（方法帧 `[this, a1..aN]`）、原生覆写调用区槽 0--见 ObjNativeFn 契约「方法调用形态」）。访问器 `method()`/`receiver()`/`name()`（绑定的方法对象之名：闭包 fn 名 / 原生 name_，ObjString* 恒非空；非虚、.cpp 定义，需 ObjClosure/ObjNativeFn 完整类型；与各 name-bearing Obj* 的 name() 同约定，供 debug_repr 渲染共用）。地址哈希型；`equals` 默认地址相等（绑定按身份判等：同一方法绑不同实例是不同对象）；`trace` 标 method_ + `mark_value(receiver_)`（两者皆装箱任意对象，值级联）；`debug_repr()` 渲染 `<bound method m>`（基类 to_string 默认委托之，显示同文案）。工厂 `new_bound_method(gc, Value, Value)` 不替调用方守卫入参，只做一次 `new_object`、无内部新建；调用方须在调用前自行根化 method 与 receiver 中的对象（LOAD_FIELD 路径 instance 仍 peek 在栈、方法值在类表内可达），返回对象白色无根须立即发布进根（LOAD_FIELD 先写回原槽根化再回填缓存）。
- `object/ObjNativeFn.hpp`/`.cpp`：原生函数对象（`ObjNativeFn final : Object`，`ObjType::NATIVE_FN`），把 C++ 函数包成 aria `Value`，供 builtins 与嵌入 API 用。签名 `using NativeFn = bool (*)(AriaVM& vm, Span<Value> slots)`：`slots[0]`=槽 0（callee/返回槽，原生函数把返回值写于此）、`slots[1..argc]`=实参（`argc=slots.size()-1`，天然变参、不存 arity，fn 自查元数）；返回 `bool`（true=成功写槽 0、false=失败），`vm.fail`/`vm.raise` 置 `Movement` 挂起错误寄存器并返回 `false`，故失败路径惯用一行 `return vm.fail(...)`。`CALL` 命中时不进帧同步直接调用，VM 以 bool 为成败信号、寄存器为错误载荷（debug 断言 `ok == !has_error()`）。详见 `.claude/reference/runtime/vm-design.md` §4.7。持 `ObjString* name_`（**恒非空**，ctor ASSERT--无具名需求者用 `kAnonymousName`（`"<anonymous>"`，定义于 `src/aria.hpp` 项目级定义头，与 ObjFunction 的 lambda 命名一致）经 `new_native_fn(gc, fn)` 匿名重载自动 intern；渲染 `<fn <anonymous>>`）+ `NativeFn fn_`（恒非空）；访问器 `name()`/`fn()`；地址哈希型；`trace` 标 name_；工厂 `new_native_fn(gc, name, fn)` **不替调用方守卫入参**，只做一次 `new_object`；调用方须在调用前自行根化 name（intern weak root），fn 为标量无需入根。匿名重载 `new_native_fn(gc, fn)` 内部 `new_string(kAnonymousName)` 驻留并自守（工厂守「自己创建的」），调用方无需根化。
- `object/ObjException.hpp`/`.cpp`：异常对象（`ObjException final : Object`，`ObjType::EXCEPTION`，非拷贝/非移动）：VM 检测到的运行时错误 / 原生函数报错的装箱载荷（M3 try/catch/throw 异常通道的运行时载体之一）。持 `ErrorCode code_`（机器标识：分类/名称经 `to_string(ErrorCode)`/`category_of` 再取，同 Error）+ `ObjString* message_`（**完整烘焙消息串**，与 `Error::message()` 同形--含 `"Category: Name"` 前缀（运行期装箱**不含位置前缀**，位置由未捕获出口的 at 跟踪行给出；经 load_module 透传的编译期 Error 消息自带 `path:line:col:` 位置，原样保留）；intern 驻留同指针，**恒非空**--ctor ASSERT，无消息错误以空串 intern 兜底）。**message_ 原样存调用方传入的已烘焙串、工厂不经 `make_message` 做任何加工**：烘焙发生在 raise 侧（经 `Error::make_message` 烘齐，`from_detail` 同源经它），`to_error()` 经 `Error::from_baked` 也**原样回传**（跳过 `make_message` 重烘--否则双重前缀）。位置不丢、catch 的 print(e) 渲染完整消息不退化；边界文案/测试断言与 Error 直构逐字一致（定稿见 `.claude/reference/runtime/exception-implementation-pitfalls.md` 坑 #7）。访问器 `code()`/`message()`。`to_error()`（定义在 .cpp）经 `Error::from_baked(code_, message_->view())` 还原为边界 Error（Error 自有 String，产物脱离 GC，异常本体被回收后仍可读；供测试/嵌入方断言 -- VM 未捕获出口经 `uncaught_error_parts` 直读 `code_`/`message_` 同源拆件，不中转 Error）；`trace()` 标 message_（唯一 GC 子节点）；`size()` = sizeof 壳；`debug_repr()` 渲染完整烘焙消息（基类 to_string 默认委托之，M3 catch 的 `print(e)`/`str(e)` 显示 `"Category: Name detail"` 同款文案）。地址哈希型；`equals` 默认地址相等。工厂 `new_exception` 两形态：`new_exception(gc, code, StringView message)` 入参是 **StringView 的已烘焙完整消息串**（如 `err.message()`/`Error::make_message` 产物）；`new_exception(gc, const Error&)` 便捷重载收**已烘焙完整消息**的 Error（公开构造面产物皆然），code + message 逐件转发上一形态、原样装箱不经 make_message 重烘（否则双重前缀），与 `to_error()` 的 `from_baked` 反向桥对称：内部 `new_string` 驻留并自行守卫跨下方 `new_object`（工厂守「自己创建的」），调用方无需手动建串根化；返回对象白色无根，须立即发布进某根（如 `ctx.raise(Value::from_obj(...))`--入寄存器后由 VM 根 tracer 标 pending_error 保命）。**注意区分**：本类承载**解释器报告的错误**；aria 语言自身 throw（M3）抛任意 Value，不限定 ObjException。
- `object/ObjModule.hpp`/`.cpp`：模块对象（`ObjModule final : Object`，`ObjType::MODULE`，非拷贝/非移动），aria 的「模块 = 命名空间」（非类），一个源文件 = 一个模块。模块的绝对文件路径（= VM 模块表查重键）由 `dir_ + name_` 合成：`dir_ + "/" + name_ + ".aria"`；切分由 `fs::module_name_and_dir` 按命中文件的绝对规范路径做：`name_` = basename 去 `.aria` 后缀（stem），`dir_` = dirname。即 `dir_` 是「模块文件所在目录」、`name_` 是「模块文件名去扩展名」--就是路径的 dirname/stem 切分（`name_` 恒为单段 stem，不支持「相对源根的多段路径」语义，不依赖源根概念）。持 `ObjString* name_`（文件名去 `.aria` 后缀/stem，intern，显示名 + 合成绝对路径用，**指针恒非空**、内容可空--ctor ASSERT，合成顶层 `<script>`/REPL 等均以非空 intern 串构造）+ `ObjString* dir_`（模块文件所在目录，intern，指针恒非空、内容可空：cwd 不可用时 `new_module` 以空串兜底）+ `ObjFunction* entry_`（模块体，顶层语句编进的 arity 0 匿名函数，主入口名 `<main>` / 导入名 `<module>`，导入时 run-once；可为 nullptr）+ `AriaHashTable globals_`（模块级绑定表，顶层 var/fun/def 的目标，`LOAD/STORE/DEF_GLOBAL` 操作此表；惰性分配）。**无加载状态字段**：加载事实源 = VM 模块表成员资格（未入表 = 未加载；入表 = 已编译待 run-once 或已跑完，run-once 与循环导入「命中即复用半初始化对象」语义均由表承载，不在对象上另设 `ModuleState` 之类的冗余第二事实源）；访问器 `name()`/`dir()`/`globals()`（非 const + const）/`entry()`/`set_entry(ObjFunction*)`。`abs_path()` 合成绝对文件路径（= VM 模块表查重键形式）：`dir_` 内容空 -> 返空串（无目录锚点）；`name_` 内容空串 -> 仅返 `dir_`；否则 `dir_ + "/" + name_ + ".aria"`（供 IMPORT 相对导入取 dirname 作基；name_/dir_ 指针恒非空，不判 nullptr）。地址哈希型；`equals` 保持默认地址相等（模块按身份判等）；`trace()` 标 name_ + dir_ + entry_ + 委托 `globals_.trace`；`debug_repr()` 渲染 `<module name>`（name_ 恒非空，内容空时渲染 `<module >`；基类 to_string 默认委托之，显示同文案）。工厂 `new_module(gc, name, dir)`（显式目录，dir 指针须非空）/ `new_module(gc, name)`（无显式目录取 cwd，不可用空串兜底）/ `new_module(gc, StringView name)`（name 以 StringView 传入，工厂内部 `new_string` 驻留并自行守卫，调用方无需手动建串根化）/ `new_module(gc, StringView name, StringView dir)`（name 与 dir 均以 StringView 传入，工厂内部 `new_string` 驻留 name/dir 串并自行守卫，调用方无需根化任何入参；dir 原样 intern 调用方给的串，空串即空串锚点，**不替调用方做 cwd 退化**--需退化用 2 参 StringView 重载）**不替调用方守卫入参**：3 参 `ObjString*` 版只做一次 `new_object`，调用方须自行根化 name 与 dir；`ObjString*` 2 参版内部新建 dir_str（cwd 串）故自行守卫 dir_str（工厂守「自己创建的」），但 name 仍须调用方根化；`StringView` 两版内部新建的 name_str/dir_str 均自行守卫，调用方无需根化任何入参。

- `object/iterator/ObjIterator.hpp`/`.cpp`：迭代器基类（**首个非 final 的 Object 子类型**，`ObjType::ITERATOR`——语言层单数类型名，`type(it)` 恒 "Iterator"）：迭代协议的**引擎缝**（源码住 `object/iterator/` 子目录，每源一对文件）。每源一个小子类、各持自然游标，基类钉纯虚契约：`has_next() const noexcept -> bool`（纯查询无分配无 fail，故不收 vm）、`next(AriaVM&) -> Opt<Value>`（取下一元素并推进游标；越界 `return vm.fail(IterationExhausted)` 一行，FailSignal 哨兵）、`trace`（各子类标各自的源，纯虚钉住忘标=编译错）、`size()`（各子类 sizeof 自身）。`load_field` override 基类一次全子类共享（与 ObjList::load_field 同形：直调 VM 的 Iterator bootstrap 类协议查表、命中自持 `new_bound_method` 恒绑定 this；store_field 不 override）；debug_repr 渲染 `<iterator>`（对标 `<upvalue>` 稳定短文案，源类型不进文案）；equals 默认地址判等（同一容器的两个迭代器是不同对象）。语言方法面（has_next/next 经 Iterator 类表恒绑定，原生是本缝的薄壳）住 `runtime/builtins/IteratorBuiltins`。子类四枚全落地（条目见下）。
- `object/iterator/ObjListIterator.hpp`/`.cpp`：list 迭代器（`ObjListIterator final : ObjIterator`）：`ObjList* list_`（被遍历者，恒非空 ctor ASSERT，经 trace 标根、元素经 ObjList::trace 级联）+ `usize cursor_`（下一元素下标，单调 +1；**下标式游标不悬垂**——元素缓冲扩容搬迁、下标仍有效，指针式则悬垂）。`has_next` = cursor < 元素数；`next` 越界 fail `IterationExhausted`（"iterator exhausted"，forIn 靠 has_next 把关、仅手写滥用触此），否则返回元素拷贝并推进。迭代中变更容器不设防（v1 不承诺）：push 的新尾会被遍历到、pop 缩界后越界由 fail-fast 拦住。工厂 `new_list_iterator(gc, list)` 一次分配无内部新建；调用方须已根化 list（iter_fn 路径在 slots[0] 栈根），返回白色建成即写回槽发布（铸造口 iter 住 `runtime/builtins/ListBuiltins`）。
- `object/iterator/ObjStringIterator.hpp`/`.cpp`：string 迭代器：`ObjString* str_`（恒非空 ctor ASSERT，经 trace 标根）+ 字节偏移游标 `offset_`，按码点步进（`utf8::decode_one` 解码，推进宽度 = 码点字节宽，恒停字符边界）；`next` 每步产出该码点的 1-char string（`utf8::encode`，与 `s[i]` 产出形态一致）。string 不可变，无迭代中变更问题。工厂 `new_string_iterator(gc, str)`（铸造口 iter 住 `runtime/builtins/StringBuiltins`）。
- `object/iterator/ObjMapIterator.hpp`/`.cpp`：map 迭代器：`ObjMap* map_`（恒非空 ctor ASSERT，经 trace 标根）+ `HashTable::const_iterator` 只读游标（跳空槽/墓碑，推进即占用槽序）；`next` 每步产出 `[k, v]` 二元 list（每步一次小分配，计划 D4 拍板接受）。迭代中变更容器不设防（v1 不承诺）：rehash/compact 搬迁槽位使游标失效，由「不承诺」兜住。工厂 `new_map_iterator(gc, map)`（铸造口 iter 住 `runtime/builtins/MapBuiltins`）。
- `object/iterator/ObjRangeIterator.hpp`/`.cpp`：range 迭代器：五对迭代器中唯一无源对象者--range 不可变，ctor 期把端点拷成标量自足（`current_`/`to_`/`is_exclusive_`/`forward_`，trace 空体）。方向构造期定向（from>to 即倒序：含上界 `10..1` 产出 10→1、不含上界 `10...1` 产出 10→2）；无上界开区间 `has_next` 恒真、方向恒正序；空区间只剩 from==to 且不含上界。工厂 `new_range_iterator(gc, range)` 只读源的三标量不持有（铸造口 iter 住 `runtime/builtins/RangeBuiltins`）。
