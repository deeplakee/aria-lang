# object 层模块参考

- `object/Object.hpp`：`Object` 基类（`next_` 链/`hash_`/`type_`/`is_marked_`）+ `ObjType`（BASE/STRING/FUNCTION/NATIVE_FN/UPVALUE/CLASS/INSTANCE/BOUND_METHOD/LIST/MAP/MODULE/RANGE/ITERATOR/EXCEPTION）；虚 `trace(GC&)`/`size()`/`equals(const Object*)`（== 内容相等，默认 `this==other`，子类型按内容 override）/`to_string()`（基类默认 `<Type at 0xaddr>`，子类型 override）/`~Object`；`debug_repr()`（**非虚**，产出 `<Type at 0xaddr>` 地址型描述，`to_string()` 基类默认委托之；供 `format_value_debug` default 分支等不可重入调试上下文调用--不经虚分派，避免重载 `to_string()` 重入 VM）；公共访问器 `hash()`/`type()`/`is_marked()`/`mark()`/`unmark()`（GC 标记用）/`type_name()`（非虚 constexpr，委托 `to_string(ObjType)` 取 `type_` 的 PascalCase 类型名如 `String`/`NativeFn`/`Module`，供错误消息类型名打印与默认 `to_string` 渲染；类型名纯由 `type_` 决定故子类无需 override）。地址哈希经 `util::hash_addr` + 两 ctor（内容哈希 `Object(u32,ObjType)` / 地址哈希 `Object(ObjType)`）。`as<T>`/`is<T>` 模板仅 `Object*`/`const Object*` 重载（DEBUG `dynamic_cast`，否则 `static_cast`；`is<T>` 目前一律 `dynamic_cast`，子类型落地后改 `ObjType` 查表，见代码 TODO）。**类型判断/转换约定（强制）**：对 Object 子类型做「判断单一类型后转型使用」的成对场景，一律用 `Object::is<T>(obj)` / `Object::as<T>(obj)`，**禁写 `obj->type() == ObjType::X` + `static_cast<X*>(obj)`** -- 前者自文档化且 DEBUG 享 dynamic_cast 校验、收口类型转换。`switch (obj->type()) { case ObjType::X: ... }` 多分支分派（如 `AriaVM::call_value`）属枚举分派天然合理，保留枚举写法、不必硬改。从 `Value` 出发：先 `v.is_obj()` 判对象，再 `Object::is<X>(v.as_obj())` / `Object::as<X>(v.as_obj())`（Value 层只有 `is_obj()`/`as_obj()`，无 typed 重载）。`Object.hpp` 不 include `value/Value.hpp`：`Object` 自前向声明供 `DerivedFromObj` concept 用，Value↔Object 的实现依赖置于 `Value.cpp` 一侧。自由函数 `log_obj_alloc(Object*)`（DEBUG 日志：打印地址/size/`obj->type_name()`）与 `to_string(ObjType)`（`ObjType` 枚举的静态 PascalCase 映射，如 `String`/`NativeFn`/`Module`，是类型名的**单一来源**，`Object::type_name()` 委托之）。**类型名约定全项目统一 PascalCase**（原语 `Nil`/`Bool`/`Int`/`F64`/`Obj`、对象 `String`/`Function`/`NativeFn`/...）。子类型已落地 `ObjString`/`ObjFunction`/`ObjNativeFn`/`ObjModule`。
- `object/ObjString.hpp`/`.cpp`：SSO 字符串（`kShortCapacity=15`，短串内联 / 长串 `long_chars_` 独立 buffer；`is_long()` 由 `length_ > kShortCapacity` 派生不存标志位），FNV-1a 哈希（经 `util::hash_str`）。访问器 `view()`/`length()`；`equals(const Object*)` override（先比指针 intern 命中快速路径、再比 `view()` 字符内容）；`to_string()` override 返字符内容原文（无引号，如 `hello`）。`new_string` 工厂（Phase 2 起经 GC `InternPool` 驻留：等价内容共享同一 `ObjString*`，命中不分配不 GC，未命中 `new_object` + `intern_insert`）。`new_string` 内部对 `intern_insert` 窗口**不加守卫**：`s` 虽此刻白色无根，但 `intern_insert -> InternPool::insert -> allocate<ObjString*>` 走 trivial 分配（永不触发 GC，见 `GC.hpp` 核心不变式），故 `s` 跨 insert 不会被回收。`name`/`module` 跨 `new_object` 顶部 `maybe_collect` 的守卫仍保留（那是真 GC 触发点，承重）。
- `object/ObjFunction.hpp`/`.cpp`：函数对象（`ObjFunction final : Object`，`ObjType::FUNCTION`）：持 `CodeUnit unit_` 值成员（编译器经 `unit()` 直接操作裸字段 emit）+ `ObjModule* module_`（所属模块，词法归属，构造时传入、不可变、非空；VM 据此定位「当前模块 globals」）+ `ObjString* name_`（intern 同指针；**恒非空**，ctor ASSERT 非空--入口函数名 `<main>`（主入口）/`<module>`（导入）、lambda 名 `<anonymous>`、具名函数为声明名；`<>` 是正常标识符中不可用的符号，具独特辨识度；统一「每个函数都有名字」模型）+ `u8 arity_`（参数个数，上限 255）。访问器 `unit()`（非 const + const 重载）/`name()`/`arity()`/`module()`。地址哈希型；`equals` 保持默认地址相等（函数无内容相等语义）；`trace()` 标 name_ + module_ + 委托 `unit_.trace`（常量池；module_ 回指形成 module<->entry 环，mark-sweep 三色标记天然破环）；`to_string()` 统一渲染 `<fn name>`（入口 `<fn <main>>`/`<fn <module>>`、lambda `<fn <anonymous>>`、具名 `<fn add>`）；工厂 `new_function(gc, module, name, arity)` **不替调用方守卫入参**（「每方只守自己创建的」），只做一次 `new_object`、无内部新建对象；调用方须在调用前自行根化 module 与 name（皆不保命：module 可能尚未入 VM 模块表、name 经 intern 是 weak root），跨 `new_object` 顶 maybe_collect。
- `object/ObjNativeFn.hpp`/`.cpp`：原生函数对象（`ObjNativeFn final : Object`，`ObjType::NATIVE_FN`），把 C++ 函数包成 aria `Value`，供 builtins 与嵌入 API 用。签名 `using NativeFn = bool (*)(AriaVM& vm, Span<Value> slots)`：`slots[0]`=槽 0（callee/返回槽，原生函数把返回值写于此）、`slots[1..argc]`=实参（`argc=slots.size()-1`，天然变参、不存 arity，fn 自查元数）；返回 `bool`（true=成功写槽 0、false=失败），`vm.fail`/`vm.raise` 置 `Movement` 挂起错误寄存器并返回 `false`，故失败路径惯用一行 `return vm.fail(...)`。`CALL` 命中时不进帧同步直接调用，VM 以 bool 为成败信号、寄存器为错误载荷（debug 断言 `ok == !has_error()`）。详见 `.claude/reference/runtime/vm-design.md` §4.7。持 `ObjString* name_`（**恒非空**，ctor ASSERT--无具名需求者用 `kAnonymousName`（`"<anonymous>"`，与 ObjFunction 的 lambda 命名一致）经 `new_native_fn(gc, fn)` 匿名重载自动 intern；渲染 `<fn <anonymous>>`）+ `NativeFn fn_`（恒非空）；访问器 `name()`/`fn()`；地址哈希型；`trace` 标 name_；工厂 `new_native_fn(gc, name, fn)` **不替调用方守卫入参**，只做一次 `new_object`；调用方须在调用前自行根化 name（intern weak root），fn 为标量无需入根。匿名重载 `new_native_fn(gc, fn)` 内部 `new_string(kAnonymousName)` 驻留并自守（工厂守「自己创建的」），调用方无需根化。常量 `inline constexpr StringView kAnonymousName = "<anonymous>"` 定义于本头。
- `object/ObjException.hpp`/`.cpp`：异常对象（`ObjException final : Object`，`ObjType::EXCEPTION`，非拷贝/非移动）：VM 检测到的运行时错误 / 原生函数报错的装箱载荷（M3 try/catch/throw 异常通道的运行时载体之一）。持 `ErrorCode code_`（机器标识：分类/名称经 `to_string(ErrorCode)`/`category_of` 再取，同 Error）+ `ObjString* message_`（**完整烘焙消息串**，与 `Error::message()` 同形--含 `"Category: Name"` 前缀，运行时位置标注落地后含 `"path:line:col: "` 前缀；intern 驻留同指针，**恒非空**--ctor ASSERT，无消息错误以空串 intern 兜底）。**message_ 原样存调用方传入的已烘焙串、工厂不经 `make_message` 做任何加工**：烘焙发生在 raise 侧（`Error::format`/`Error::from_detail` 构造），`to_error()` 经 `Error::from_baked` 也**原样回传**（跳过 `make_message` 重烘--否则双重前缀）。位置不丢、catch 的 print(e) 渲染完整消息不退化；边界文案/测试断言在寄存器载荷改 Value 前后不漂移（定稿见 `.claude/reference/runtime/exception-implementation-pitfalls.md` 坑 #7）。访问器 `code()`/`message()`。`to_error()`（定义在 .cpp）经 `Error::from_baked(code_, message_->view())` 还原为边界 Error（Error 自有 String，产物脱离 GC，异常本体被回收后仍可读）；`trace()` 标 message_（唯一 GC 子节点）；`size()` = sizeof 壳；`to_string()` 渲染完整烘焙消息（M3 catch 的 `print(e)`/`str(e)` 显示 `"Category: Name detail"` 同款文案）。地址哈希型；`equals` 默认地址相等。工厂 `new_exception(gc, code, StringView message)` 入参是 **StringView 的已烘焙完整消息串**（如 `err.message()`/`Error::format` 产物）：内部 `new_string` 驻留并自行守卫跨下方 `new_object`（工厂守「自己创建的」），调用方无需手动建串根化；返回对象白色无根，须立即发布进某根（如 `ctx.raise(Value::from_obj(...))`--入寄存器后由 VM 根 tracer 标 pending_error 保命）。**注意区分**：本类承载**解释器报告的错误**；aria 语言自身 throw（M3）抛任意 Value，不限定 ObjException。
- `object/ObjModule.hpp`/`.cpp`：模块对象（`ObjModule final : Object`，`ObjType::MODULE`，非拷贝/非移动），aria 的「模块 = 命名空间」（非类），一个源文件 = 一个模块。模块的绝对文件路径（= VM 模块表查重键）由 `dir_ + name_` 合成：`dir_ + "/" + name_ + ".aria"`；切分由 `fs::module_name_and_dir` 按命中文件的绝对规范路径做：`name_` = basename 去 `.aria` 后缀（stem），`dir_` = dirname。即 `dir_` 是「模块文件所在目录」、`name_` 是「模块文件名去扩展名」--就是路径的 dirname/stem 切分，不依赖源根概念（早先文档把 `dir_` 描述为「所属源根」、`name_` 为「相对源根的多段路径」如 `lib/utils`，那是设计意图而非实现现状：实现里 `name_` 恒为单段 stem）。持 `ObjString* name_`（文件名去 `.aria` 后缀/stem，intern，显示名 + 合成绝对路径用，**指针恒非空**、内容可空--ctor ASSERT，合成顶层 `<script>`/REPL 等均以非空 intern 串构造）+ `ObjString* dir_`（模块文件所在目录，intern，指针恒非空、内容可空：cwd 不可用时 `new_module` 以空串兜底）+ `ObjFunction* entry_`（模块体，顶层语句编进的 arity 0 匿名函数，主入口名 `<main>` / 导入名 `<module>`，导入时 run-once；可为 nullptr）+ `AriaHashTable globals_`（模块级绑定表，顶层 var/fun/def 的目标，`LOAD/STORE/DEF_GLOBAL` 操作此表；惰性分配）+ `ModuleState state_`。`enum class ModuleState : u8 { Loading, Loaded }`（构造置 `Loading`；循环导入命中 `Loading` 返回半初始化对象）；访问器 `name()`/`dir()`/`globals()`（非 const + const）/`entry()`/`set_entry(ObjFunction*)`/`state()`/`set_state(ModuleState)`。`abs_path()` 合成绝对文件路径（= VM 模块表查重键形式）：`dir_` 内容空 -> 返空串（无目录锚点）；`name_` 内容空串 -> 仅返 `dir_`；否则 `dir_ + "/" + name_ + ".aria"`（供 IMPORT 相对导入取 dirname 作基；name_/dir_ 指针恒非空，不判 nullptr）。地址哈希型；`equals` 保持默认地址相等（模块按身份判等）；`trace()` 标 name_ + dir_ + entry_ + 委托 `globals_.trace`；`to_string()` 渲染 `<module name>`（name_ 恒非空，内容空时渲染 `<module >`）。工厂 `new_module(gc, name, dir)`（显式目录，dir 指针须非空）/ `new_module(gc, name)`（无显式目录取 cwd，不可用空串兜底）/ `new_module(gc, StringView name)`（name 以 StringView 传入，工厂内部 `new_string` 驻留并自行守卫，调用方无需手动建串根化）/ `new_module(gc, StringView name, StringView dir)`（name 与 dir 均以 StringView 传入，工厂内部 `new_string` 驻留 name/dir 串并自行守卫，调用方无需根化任何入参；dir 原样 intern 调用方给的串，空串即空串锚点，**不替调用方做 cwd 退化**--需退化用 2 参 StringView 重载）**不替调用方守卫入参**：3 参 `ObjString*` 版只做一次 `new_object`，调用方须自行根化 name 与 dir；`ObjString*` 2 参版内部新建 dir_str（cwd 串）故自行守卫 dir_str（工厂守「自己创建的」），但 name 仍须调用方根化；`StringView` 两版内部新建的 name_str/dir_str 均自行守卫，调用方无需根化任何入参。置 `Loading` 态。
